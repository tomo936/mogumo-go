# エージェント構成の最適化の相談

状態: 未対応
宛先: Claude Code
差出人: シロ（オーナー承認済み）
優先度: 再開後の最初の作業として、他の作業より先に判断してほしい

## 相談の内容

現在の `.claude/agents/` には designer / implementer / tester の3定義があり、「設計→実装→検証」の工程を引き継ぐ形になっている。一方で運用は 2026-11-07 の決定で「リーダーが全体を持ち、サブは重い作業の隔離に使う」に変わっており、定義と運用がズレている。最近の Anthropic 公式の指針（役割ではなく文脈の境界で切る／工程の引き継ぎは伝言ゲームになる）と、2026-11-07 のトークン実測（消費の山は実装サブで、主因は前提ミスによる試行錯誤だった）に照らして、次の形への変更を相談したい。

## 提案

1. **designer と implementer の定義を廃止する。** 設計と実装はリーダーが一貫して持つ。
2. **サブは定義ファイルではなく、委任の都度、文脈の境界で切る。** 用途は2つだけ: (a) 探索（大量のファイル読み・検索・ログ処理。要約だけ返す） (b) 隔離したい重い実装（同時に1つまで、毎回まっさらから）。
3. **tester は残す。** 理由は工程ではなく権限分離（道具が読み取りだけで、書き換えられないことが保証されるため）。モデルは Sonnet のまま。
4. **モデルの既定を決める。** サブの実装は既定 Sonnet。Opus にするのは「設計で決め切れない判断が残る実装」「原因不明のバグ調査」「3Dなど空間推論が重い実装」の3つ。詰まったら途中で Opus に交代してよい。
5. CLAUDE.md に工程や役の分担として上記と矛盾する記述があれば、この形に合わせて更新する。

## 依頼

- 妥当と判断したら、上記を反映し、判断と反映内容を `handoff/to-shiro/` へ返事として書いてほしい。
- 懸念がある場合は、反映せず、懸念点を返事に書いてほしい（オーナーとシロで再検討する）。
- この相談への対応は軽く済ませ、通常の開発作業の再開を優先してよい。
