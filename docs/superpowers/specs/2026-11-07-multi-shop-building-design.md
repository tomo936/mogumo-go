# 同じ建物に複数のお店（ビル）の設計

2026-11-07。親の決定は `2026-11-06-hotpepper-checkin-design.md` §13。この段は **2〜5軒のビル** だけ。6軒以上の「大きい施設・縦長ビル」とチェックインの 50m の測り方は次の段。

## 1. ねらい
- 都心では1つの建物に何軒もお店が入っている。今は2軒目以降が輪郭なしの小さな店として道ばたに並び、「まるでそこにあるように」にならない。
- 同じ建物のお店は **ビルの模型1つ** にまとめ、上に入っているお店のピンを出す。どのお店かはピンか一覧で選ぶ。

## 2. 実データ（東京駅を中心に約7km四方、地図のお店 10,091軒、2026-11-07 調べ）
| 1つの建物のお店 | 建物の数 |
|---|---|
| 1軒 | 4,549 |
| 2〜5軒 | 1,141（2軒 751・3軒 247・4軒 101・5軒 42） |
| 6軒以上 | 86 |
| 輪郭の外 | 1,918軒 |

お店のある建物の約2割がビルになる。数え方の台本は残さない（作業用フォルダ）。

## 3. 決まったこと（本人）
- まとめるのは「同じ建物の輪郭の中にお店の点がある」ときだけ。住所の建物名の突き合わせは今回しない（2026-11-07 本人 OK）。迷えばまとめない。
- ビルの見た目はシロの見本 `art/reference/shops/building-multi.png`（クリーム色・3階・屋上にタンクと室外機・1階に店先2つ）。ショーケースの中身はどの店にも見える汎用の中身（あたたかい明かり・カウンター・小さなテーブル）。お店の種類はピンで見せる。
- ピンはビルの上で少しずつずらして全部出す（縦積みは却下）。ピンをタップ → そのお店のシート。イメージ `art/prototypes/pins-layout-mock.png` ①。
- 遠く（縮小）でピンがつぶれるときは1つ＋「済み/全部」にまとめる。
- ピンの絵はシロ作成中。届くまでは仮の丸（種類の色＋絵文字なし）。
- チェックインの 50m は今どおりお店の点から測る（ビルは輪郭が小さいので困らない）。

## 4. 進め方の候補
- **A. 見えている店だけでまとめる（採用）**: 毎回の更新で、出す店（`visibleShops` の結果）を輪郭ごとに分ける。霧が晴れて仲間が見えると、1軒の店がビルに変わる。今の「店ごとに置き方を1回だけ計算」の仕組みにそのまま乗る。
- B. 全部の店でまとめ、見えている仲間のピンだけ出す: 霧の中のお店の存在がビルの形でばれる。霧のねらいに合わない。
- C. 住所の建物名でもまとめる: 地図だけのお店には住所が無く、効果が小さい。手間が大きい。

## 5. 仕組み
### domain（純粋な計算）
- `src/shops/domain/grouping.ts`（新規）: 店の点（m）と建物の輪郭（m）から、**いちばん小さい、点を含む輪郭** ごとに店を分ける。2軒以上の組を「ビル」、1軒と輪郭の外は今どおり1軒の店。6軒以上もこの段では「ビル」として扱う（次の段で大きい施設に置き換える。ピンは1つ＋数字、§5 ピン）。
- 置き方は既存の `fitFootprint`（輪郭の真ん中・道路向き・大きさ）を使う。ビルの大きさの上限は1軒の店より大きくしてよい（例 14〜22m、`config.ts` に `BUILDING_MAX_SIZE_M`）。

### infra
- 模型: `src/assets/shops/building.glb`（Blender で見本に合わせて作る。台本は `art/prototypes/blender-building.py`）。`shopLayer` は種類 `building` も1つの模型として読む（`ShopKind` には足さない。層の中の「模型の名前」として扱う）。
- タップ: `pick` は店の id かビルの id（`bldg:<先頭の店の id>` など）を返す。
- ピン: `src/shops/infra/buildingPins.ts`（新規）。チェックの印と同じ HTML マーカー。ビルの上に、入っている店の数だけ横に少しずつずらして並べる。済みの店のピンには ✓。ピンのタップで、その店の id を返す。ビルに入った店には、別のチェックの印は出さない。
- 遠くのとき: ズーム 16 未満（`config.ts`、作る段で見て調整）は1つ＋「済み/全部」（例 1/3）。タップでビルの一覧。

### ui
- ビルをタップ（またはまとめたピンをタップ）→ **お店の一覧のシート**（新規 `BuildingSheet`）: 店名・種類の色・済みの印。並びは近い順でなく名前の順（同じ建物なので距離はほぼ同じ）。行をタップ → 今の `ShopSheet`。
- ピンを直接タップ → 今の `ShopSheet`。
- チェックインの流れ（50m・1日1回・演出・霧の波）は変えない。紙ふぶきと帯はその店の位置で出す。

## 6. しないこと
- 6軒以上の大きい施設の立体（実際の輪郭を立体に）・屋根の上に散らばるピン・階の順の一覧 → 次の段
- チェックインの 50m を輪郭から測る変更（サーバーも変わるので本人決定が要る）→ 次の段
- 住所でのまとめ・ピンの本物の絵（シロ待ち）

## 7. 作る人に任せること
- ピンのずらし幅・高さ、まとめるズームのしきい値、ビルの大きさの上限は、実機の画面を見て決める（`config.ts`）。
- 模型の三角形の数は1軒の店と同じくらい（重さの目安として計画に数字を書く）。

## 8. 変更: 大型かどうかは建物の広さで決める（2026-11-07 本人 OK、実機確認のあと）
- 実機で「大きい施設がビル表記、ちょっとしたビルが大型表記」になった（お店の数で分けていたため）。
- **輪郭が 2,500m² 以上で2軒以上 → 大型の施設**（ピン1つ＋「済み/全部」、拡大しても同じ）。模型は次の段で実際の輪郭の立体にするまで仮にビル。
- **それより小さい建物 → 何軒でもビル**。ピンは5つまで並べ、6軒以上は5つ＋「+N」（押すと全部の一覧）。縮小したときは今までどおり1つ＋「済み/全部」。
- お店が1軒だけの建物は、広くても今までどおりのお店の模型。
- 境目の根拠（2軒以上の建物、2,500m² 以上）: 東京駅まわり 99棟（COREDO室町・松坂屋など）、新宿まわり 34棟（ルミネエスト・パルコ・高島屋など）。1,500〜2,500m² は高層オフィスなどが混ざるので入れない。イメージ `art/prototypes/building-size-mock.png`。
- これにより、親の設計の「6軒以上を大きい施設」「縦長ビルは1つ＋数字・階の順の一覧」は置き換え（縦長ビルは広さが小さいので「ビル＋5つ＋N」）。
