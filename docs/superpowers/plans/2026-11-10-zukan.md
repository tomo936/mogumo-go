# 図鑑（ジャンル別・シールアルバム風）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 行ったお店と、見つけたけど行っていないお店（「？」）を、ジャンル別のページに並べる図鑑を作る。カードを押すとお店のシートを開く。

**Architecture:** 純粋な計算（ページ分け・並び・埋まり数）は `src/zukan/domain/`。見つけた店は `shops` テーブル、自分の記録は `loadProgress`（既存）から読む `src/zukan/infra/`。画面は `src/zukan/ui/`（地図の上に重ねる全画面の板）。入口は探索シートの「図鑑」。

**Tech Stack:** React 19 / TypeScript / Vitest / Supabase（読むだけ・RLS）

**Spec:** `docs/superpowers/specs/2026-11-10-zukan-design.md`（仕様の元: SPEC S11・S17）

## Global Constraints
- 1ページ 12 枚（3列×4段）。ページは18ジャンルごと（`src/shops/domain/kind.ts` の順）。
- 並び: 行った店が先（最近行った順）→ 「？」の店（ジャンル内は名前順。名前は画面に出さないので、id 順）。
- 「？」の店の名前・写真・営業時間は出さない。キャッチの一言だけ（無ければ出さない）。
- 枠は `frameTier`（1〜2回 normal／3〜9回 silver／10回〜 gold）。
- 読めなかったら図鑑に「読み込めませんでした」と出す（地図は壊さない）。
- domain は React・Supabase を import しない。SQL は書き換えない（テーブルは既存）。

## Review Focus
1. 同じ店が `hp:` と `osm:` の2つの id で出る（合体前の記録）→ 1枚にまとめる。→ Task 1 のテスト。
2. 記録の無い店・記録が読めない時: 行った扱いにしない（「？」のまま）。→ Task 1 のテスト。
3. 店が1軒もない: 空のページを出さず、案内を出す。→ Task 2 のテスト。
4. 「？」の店の名前が画面の文字・画像の代替文に出ない。→ Task 3 のテスト。
5. ジャンルのページ数が 0 のジャンル: 埋まり数 0/0 を出す（ページは作らない）。→ Task 1。

### Task 1: ページ分け・並び・埋まり数（domain）

**Files:**
- Create: `src/zukan/domain/zukan.ts`, `src/zukan/domain/zukan.test.ts`

**Interfaces:**
- Produces:
  - `type ZukanShop = { id: string; name: string; kind: ShopKind; photoUrl: string | null; catch: string | null; genreName: string | null; lat: number; lng: number; visits: Visits | null }`
  - `buildZukan(shops: ZukanShop[]): Map<ShopKind, ZukanShop[]>`（同じ店は1枚にまとめる。並びは仕様どおり）
  - `pageCount(n: number): number`（12 枚ずつ。0 なら 0）
  - `filledCount(cards: ZukanShop[]): number`（`visits` があるものの数）

- [ ] Step 1: テストを書く: `buildZukan` で「行った店が先・最近順」「未訪問は後ろ」「hp と osm の2つ id は1枚（記録は合算）」「記録 null は未訪問扱い」。`pageCount(0)=0, (12)=1, (13)=2`。`filledCount` は visits のある数。
- [ ] Step 2: 失敗を確かめる → 実装 → 通す。
- [ ] Step 3: Commit `feat(zukan): page and order rules`

### Task 2: 見つけた店と記録を読む（infra）

**Files:**
- Create: `src/zukan/infra/zukanApi.ts`, `src/zukan/infra/zukanApi.test.ts`

**Interfaces:**
- Consumes: `loadProgress`（`src/checkin/infra/checkinApi.ts`、`visitsByShop` を返す）, `kindFromHotpepper`（`src/shops/domain/kind.ts`）
- Produces: `loadZukan(client?): Promise<ZukanShop[]>`（`shops` を読み、`loadProgress` の visits を付ける。`shops` の行は `genre_code`・`genre_name`・`catch`・`photo_url`・`lat`・`lng`・`name`・`shop_id`）

- [ ] Step 1: テスト（偽のクライアントで）: 行の変換（`kind` は `kindFromHotpepper(genre_code, name)`）／`visitsByShop` がある店だけ `visits` が入る／読み込み失敗で throw。
- [ ] Step 2: 実装（`shops` は `select` の後、`range` で 1000 行ずつ読む。既存 `readAll` と同じ形にする）。
- [ ] Step 3: Commit `feat(zukan): load seen shops with my visits`
