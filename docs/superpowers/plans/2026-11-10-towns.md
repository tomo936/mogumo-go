# 町の機能（クリア・コンプリート・制覇率） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** お店に行くと町ごとの進み具合が進み、半分でクリア（町全体の霧が晴れる・+100）、全部でコンプリート。全国で動き、無料の枠に余裕を残し、チェックインを重くしない。

**Architecture:** 町の境目は e-Stat から1回だけ作り、0.25度の格子ごとの gzip ファイルで Supabase の非公開バケット `towns` に置く。Edge Function `towns` が「行った店の町を決める → その町のお店を地図タイルから数えて `towns` の行に覚える → 判定して `grant_town` で記録とコインを書く」。アプリはチェックインのあとと記録を開いたときにこの関数を呼び、クリアした町の形から見えている範囲だけ霧のセルを作る（サーバーに町のセルは保存しない）。

**Tech Stack:** Deno（Supabase Edge Functions、`npm:@mapbox/vector-tile@2`・`npm:pbf@4`・`npm:@supabase/supabase-js@2`）、Postgres（migration 0005）、Node 26（境目のファイル作り。`.ts` をそのまま実行）＋ mapshaper（`npx`、版を固定）、React 19 / TypeScript 7 / Vitest。

**Spec:** `docs/superpowers/specs/2026-11-10-towns-design.md`（2026-11-10 オーナー承認。§11 の3点も承認）

## Global Constraints

- 町の単位: 同じ市区町村（PREF＋CITY）の中で、`S_NAME` の末尾の「◯丁目」を取った町名でまとめる。水面（HCODE 8154）は除く。`town_id` = `<PREF><CITY>-<町名>`（例 `13112-経堂`）。
- クリア: 行った数 ≥ ⌈全部の数 ÷ 2⌉（全部の数 1 以上）→ +100 コイン（町ごとに1回）。コンプリート: 行った数 = 全部の数。コインなし。一度取ったものは消さない。
- 分母 = 町の一覧（地図の名前つき飲食店）＋ その人が行った「一覧に無い店」。同じ店とみなす決まり: `osm:` の番号が同じ、または 40m 以内で店名が互いを含む（`checkin/core.ts` の `MATCH_M`・`namesMatch` と同じ）。
- お店の種類は `checkin/core.ts` の `FOOD` と同じ8種。タイルは OpenFreeMap z14 の `poi` 層。
- 1回の呼び出しで読むタイルは最大 40 枚、格子のファイルは最大 3 つ、町を決める店は最大 20 軒。一覧は 30 日で数え直す。
- `fog_cells` に町のセルを入れない。チェックインの関数（`checkin`）は変えない。
- 判定はサーバー。ユーザーは JWT からだけ決める。位置・店の id・ユーザーの id をログに出さない。`service_role` キーはブラウザ側に入れない。`.env` は読まない。
- 出典の文: 「出典: 政府統計の総合窓口（e-Stat）」「『国勢調査 町丁・字等別境界データ』（総務省統計局）を加工して作成」。
- コードの決まり（CLAUDE.md）: `import type`、拡張子つき import、`enum` などを使わない、domain は React・MapLibre・Supabase を import しない、依存は ui → infra → domain。
- 各タスクの終わり: `npm test`・`npx tsc -b`・`npm run lint`（警告 33 が基準。増やさない）を通してコミット。dev へ送るのは最後の1回だけ（Vercel の1日の上限）。

## Review Focus

1. **町のクリアはチェックインの数秒後に書かれる**（`conquered_at` は最後のマスの時刻より後）。記録のスライダーの右端で、その町が晴れて見えること → Task 7（`timeRange` に町の時刻を入れる）。
2. **形が離れた町（島など）**: 外側の四角で格子・タイルを決めると何百にもなる。部品（Polygon）ごとに決めること → Task 1（`chunkKeysForGeometry`・`tilesForGeometry`）。
3. **数えている途中で関数が止められる・タイルが読めない**: 途中までの結果を失わず、次の呼び出しで続きから。チェックインは成功のまま → Task 3（10 枚ごとに保存）・Task 5（失敗は null、画面は止めない）。
4. **同じ店を `hp:` と `osm:` の両方でチェックインした人**: 行った数を2と数えない → Task 1（`progress`）。
5. **広い町（数百km²）**: アプリは見えている範囲（地図 2,000m・記録 3,000m）だけセルにする。全部をセルにしない → Task 4（`cellsInTown` は四角で切る）。

### Task 3: Edge Function `towns`（`index.ts`・`tiles.ts`）

**Files:**
- Create: `supabase/functions/towns/index.ts`, `supabase/functions/towns/tiles.ts`

**Consumes:** Task 1 の全部、Task 2 の列と `grant_town`。
**Produces（返事の形。アプリの Task 5 が読む）:**
```json
{ "towns": [{ "id": "13112-経堂", "name": "経堂", "city": "世田谷区", "visited": 3, "total": 12,
              "cleared_at": null, "completed_at": null, "counting": false, "last_at": "2026-11-10T03:00:00Z" }],
  "newly": [{ "id": "13112-経堂", "name": "経堂", "kind": "clear", "coins": 100,
              "town": { "city": "世田谷区", "area_m2": 1234567, "boundary": { "type": "Polygon", "coordinates": [] }, "at": "2026-11-10T03:00:05Z" } }],
  "more": false }
```
`newly` の `town` は `kind: 'clear'` のときだけ。`complete` は `coins: 0`・`town: null`。

- [ ] **Step 1: `tiles.ts`**（Deno）: `tileTemplate(): Promise<string>`（TileJSON `https://tiles.openfreemap.org/planet` の `tiles[0]`）、`fetchTilePois(x, y, template): Promise<PoiFeature[]>`（`poi` 層の点。404・204 は空。失敗は `UpstreamError`）。`checkin/osmTile.ts` と同じ読み方・同じ 15 秒の時間切れ
- [ ] **Step 2: `index.ts`** の流れ（`checkin/index.ts` と同じ CORS・JWT の確かめ方・エラーの返し方）
  1. その人の `checkins`（`shop_id, checked_in_at`、1000 行ずつ全部）→ 店ごとの最後の時刻
  2. `shops`（`shop_id, name, lat, lng, town_id, town_checked_at`、100 件ずつ）
  3. 町を決める: `town_id` も `town_checked_at` も null の店を最大 `SHOPS_PER_CALL`。`chunkKey` ごとにまとめ、最大 `CHUNKS_PER_CALL` のファイルをバケット `towns` の `g/<key>.json.gz` から読む（`DecompressionStream('gzip')`。無ければ町なし）。`findTown` で見つかれば `towns` に行を入れる（あれば何もしない: `town_id, name, city_name, area_m2, boundary, min_lat, max_lat, min_lng, max_lng`）→ `shops` の `town_id` と `town_checked_at` を書く。見つからなければ `town_checked_at` だけ。残りがあれば `more = true`
  4. その人の町（店の `town_id` の集まり）の `towns` の行（`town_id, name, city_name, shops, counted_at, count_state`。**`boundary` はここでは読まない**）
  5. 数える: `shops` が null、または `needsCount` の町を **1回の呼び出しで1つだけ**。`boundary` を読み、`count_state` が無ければ `{ tiles: tilesForGeometry(boundary, TILE_Z), next: 0, shops: [] }`。`TILE_BATCH` 枚ずつ並べて読み、`foodInTown` → `mergeShops`、**1束ごとに `count_state` を保存**。`TILES_PER_CALL` 枚で止める。終わったら `shops`・`counted_at` を書き `count_state` を null に。タイルが読めなければその回は止める（状態は残す）。数える町がまだあれば `more = true`
  6. 判定: `shops` がある町ごとに `progress`（行った店 = その町の `shops` の行）→ `judge`。`town_conquests`（その人の分）と比べ、新しいクリア・コンプリートがあれば `grant_town`。返ってきた `newly_cleared`・`newly_completed` が真のものだけ `newly` に入れる（クリアなら `boundary`・`area_m2` を読んで付ける）
  7. 返す。`counting` = `shops` が null（初めて数えている途中）。数え直しの途中は古い一覧で判定を続ける
- [ ] **Step 3:** `npx tsc -b`・`npm run lint` は対象外のファイルだが、`npm test` が全部通ること。Deno の型は確かめられないので、`checkin/index.ts` と同じ API だけを使う
- [ ] **Step 4:** コミット `feat(towns): edge function towns (assign towns, count shops from tiles, judge, grant)`
