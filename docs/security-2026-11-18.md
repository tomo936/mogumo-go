# セキュリティ診断への対応（2026-11-18）

診断: ギルベルト（リポジトリの静的解析、オーナー承認済み）。Critical 0／High 0／Medium 4／Low 4。RLS の水準は高く、SQL インジェクション・service_role キーのフロント露出・XSS は検出なし。

## 対応

| # | 指摘 | 対応 | 場所 |
|---|---|---|---|
| 1 | セキュリティヘッダーが無い（クリックジャッキング） | `Content-Security-Policy: frame-ancestors 'none'`・`X-Frame-Options: DENY`・`X-Content-Type-Options: nosniff`・`Referrer-Policy: strict-origin-when-cross-origin`・`Permissions-Policy: geolocation=(self)`。CSP の本体（script-src など）は MapLibre・地図タイル・Turnstile・Supabase の許可リストの設計が要るので、段階導入（未） | `vercel.json` |
| 2 | 関数にユーザー単位の回数の上限が無い | 関数ごとに 10 分あたりの上限（ホットペッパー 40・地図のお店 60・気配 30・ミッション 60・町 150・チェックイン 60・退会 5）。超えたら 429。数えるのは DB（`rate_limit_hit`、関数だけが呼べる）。数え損ねたときは止めない。手元で 30 回目まで通り 31 回目から 429 を確認 | `supabase/migrations/0017_rate_limits.sql`・`supabase/functions/_shared/rateLimit.ts` |
| 2' | ホットペッパーの同一エリアの再取得間隔 | 上の回数の上限で代える。エリアごとの使い回し（キャッシュ）は未（必要になったら） | — |
| 3 | 関数の CORS が `*` | 本番 `https://mogumo-go.vercel.app`・開発 `https://mogumo-go-dev.vercel.app`・手元（localhost／127.0.0.1）だけに返す。手元の Supabase は入口（Kong）が `*` で上書きするので手元では確かめられない。**本番で確かめる（下）** | `supabase/functions/_shared/cors.ts`（7 本の入口を `withCors` で包む） |
| 4 | 秘密の混入検査が pre-commit だけ | GitHub Actions で push・PR のたびに gitleaks。手元で全履歴（663 コミット）を検査して 0 件 | `.github/workflows/security.yml` |
| 5 | 依存の CVE 照合が無い | 同じ Actions で `npm audit`（本番で配る部品は high 以上で失敗）＋ Dependabot（週 1）。2026-11-18 時点: 本番で配る部品 0 件。開発用の道具（vite・vitest の picomatch ReDoS）に high 6 件。npm の提案が古い版への戻しなので入れない（利用者に届かない） | `.github/workflows/security.yml`・`.github/dependabot.yml` |
| 6 | `record_snapshots` の集計値が自己申告 | 今はアプリのどこからも使っていない（本人しか読めない）。**決まり: ランキングなど他人と比べる所に使うときは、`checkins` などの実績からサーバーで計算し直す。自己申告の値は使わない** | この文書 |

保留（オーナーの方針待ち・実装しない）: チェックイン位置の自己申告（GPS 偽装）への緩和策。
情報: 本番の Email プロバイダーはギルベルトが無効化済み（Google と匿名は有効）。

## 本番に入れる手順（オーナー）

1. **SQL 0017**: 本番の Supabase（`mogumo-go`）→ SQL Editor に `supabase/migrations/0017_rate_limits.sql` を全部貼って Run（Ubuntu で `cd ~/mogumo-go && clip.exe < supabase/migrations/0017_rate_limits.sql` でコピーできる）。
2. **関数 7 本を置き直す**（CORS と回数の上限が入る）: Ubuntu で
   ```
   cd ~/mogumo-go
   npx supabase login
   npx supabase functions deploy --use-api --project-ref jaypeaejbzkeudwvvrnb
   npx supabase logout
   ```
   - 1 より先に 2 をしても壊れない（数え損ねは止めない作り）が、上限が効くのは 1 のあと。
3. **画面（ヘッダー・ホーム画面のアプリ化）**: `dev` を `main` に入れると Vercel が本番に出す。
4. **確かめる**:
   - CORS: Ubuntu で `curl -s -D - -o /dev/null -X OPTIONS -H "Origin: https://evil.example" https://jaypeaejbzkeudwvvrnb.supabase.co/functions/v1/checkin | grep -i access-control-allow-origin` → **何も出なければ OK**。`Origin: https://mogumo-go.vercel.app` にすると `access-control-allow-origin: https://mogumo-go.vercel.app` が出る。
   - ヘッダー: `curl -sI https://mogumo-go.vercel.app | grep -i "x-frame-options\|content-security\|nosniff"` で 3 行出る。
   - GitHub: リポジトリの Actions に `security` が緑で出る。
