# もぐもGO UI/UX 評価と大規模見直し案（2026-11-23）

正本。スマホで見るページは https://claude.ai/artifact/（この資料と同じ中身。画面の写真つき）。
材料: 全画面の撮影（art/qa/uiux-2026-11-23/、45 枚。リポジトリ外）、CSS の集計、参考資料（docs/uiux/2026-11-23-references.md・ai-look.md）。

## 1. 総評
いちばん良い画面（ログインボーナス・地図の上の丸いボタン・タイトル）は、もう「ゲームの絵」になっている。
安っぽさと AI っぽさの元は、**同じアプリの中に「ゲームの絵の画面」と「ふつうの Web の画面」が混ざっていること**。
設定・記録・初回設定・お店のシートの文字の部分は、どこにでもある Web の部品（端末の標準字体・緑のスイッチ・白い角丸の箱）のままで、絵の画面と並ぶと急に安く見える。

| 観点 | 点（10 点） | ひとこと |
|---|---|---|
| 絵の魅力（タイトル・ボタン・ボーナス） | 8 | ここは有名アプリに近い |
| 統一感（色・字体・形） | 3 | 色 225・影 86・角の丸み 35・文字の大きさ 36 通り。字体は図鑑と感想だけ丸ゴシック |
| 絵の画風のそろい | 4 | アニメ調（タイトル）・水彩（キャラ選び）・つやのある 3D 描画（お店の写真）・平らなピン、が並ぶ |
| ごほうびの気持ちよさ | 4 | ログインボーナスは良い。チェックインは Web の「完了」の緑の帯で、いちばん大事な瞬間が一番素っ気ない |
| 地図の見やすさ | 6 | 町の 3D は魅力的。まとめの数字の丸・灰色のフォークのピン・赤い 0/6 の札・白い名札が混み合う |
| 文の調子 | 5 | 「地図のデータのお店」「EXP」「記録のかぎ」など作り手の言葉が残る。ポコタン以外の文に声が無い |
| 空っぽの画面 | 3 | お店の詳しい画面の下半分、記録の空の地図（文字とピンが重なる不具合）、図鑑の紫の「？」が全部同じ |

## 2. 色を外れている所（AI っぽさが一番出ている所）
- チェックイン完了の帯・設定のスイッチ: **Web サービスの緑（#3ecf8e 系）**。手帳風の世界に無い色。
- 図鑑の「？」のカード・気配のカード: **紫・ラベンダー**。ほかに紫を使う所が無い。
- 地図の「0/6」の札: **鮮やかなサーモン色**。
- 気配の距離の文字: **深緑**。
→ 緑・サーモン・深緑は「誰も決めなかった色」。役割を決めた色に置き換える。**紫は「謎」の役割のある色なので残す（12 章）。**

## 3. 見直しの方針（デザインの決まり v2）
有名アプリに共通するのは、**全画面が 1 つの決まりで作られていること**。もぐもGO は「旅の手帳（紙・こげ茶のインク・橙のスタンプ・空色のマスキングテープ）」を決まりの芯にする。

### 3.1 色（役割で 16 色前後に）
| 役割 | 色の方向 |
|---|---|
| 紙（地） | クリーム 3 段（地・カード・くぼみ） |
| インク（文字・輪郭） | こげ茶 3 段（濃い文字・ふつうの文字・薄い補足）。純粋な黒・灰色は使わない |
| 差し色（押せる物・大事な数字） | 橙 1 色＋押したときの濃い橙 |
| 空と霧（もぐもGO らしさ） | 空色 1 色（マスキングテープ・まだの所・霧）＋白の雲 |
| 済み・成功 | 緑ではなく「金のスタンプ色」（茶寄りの金） |
| 注意・削除 | 煉瓦色の赤（今の赤より茶寄り） |
| 種類の色（ピンの縁） | 今の食べ物のピンの色を、彩度をそろえた 1 セットに |

### 3.2 字体と文字の段
- 全画面を **丸ゴシック（M PLUS Rounded 1c）** にそろえる（今は図鑑・感想だけ）。見出しは太く、本文はふつうの太さで読みやすく。
- 文字の大きさは 7 段（10・12・14・16・20・24・32）。数字（コイン・距離・レベル）は等幅の数字。

### 3.3 形・影・余白
- 角の丸み 3 段（札 8・カード 16・シートと大きいボタン 24）＋丸（アイコン）。
- 影は 2 種類だけ: 「ぷっくり」（下にこげ茶の線の影。押せる物＝ボタン・カード）と「浮く」（やわらかい影。シート・窓）。今の 86 通りはこの 2 つに置き換える。
- 余白は 4・8・12・16・24・32。

### 3.4 部品（作り直してから全画面に使う）
ボタン（大・中・小・丸）／紙のカード（マスキングテープ・スタンプ枠の飾りつき）／シート（手帳のページ）／リボンの見出し（図鑑の「お店図鑑」の形を全画面へ）／札（チップ）／一覧の行／スイッチ（緑をやめ、橙とクリーム）／数字の丸ゲージ／空っぽの画面（ポコタンの絵＋一言）／**スタンプ**（チェックイン・実績・町のクリアの共通のごほうびの形）。

### 3.5 動き
- 押す: 0.06 秒で少しつぶれて 0.16 秒で戻る（全ボタン共通）。
- シート: ばねで上がり、閉じるときは下へ。
- ごほうび: スタンプが「ポン」と押される（チェックイン・実績・町のクリア）。紙ふぶきは大きい場面だけ。
- 動きを減らす設定の端末では、動きを止めて色の変化だけにする。

### 3.6 絵の画風の決まり（ChatGPT に渡す）
- 輪郭: こげ茶、太さ一定。塗り: マットで少しだけ影、ハイライトは控えめ。光は左上から。彩度は今のボタンの絵に合わせる。
- キャラのイラストの画風の違い（キャラ選びの水彩・タイトルの男の子など）は、いったん許容する（2026-11-23 オーナー）。
- 合わせ直す絵: お店の写真（つやのある 3D 描画 → 同じ模型を手帳の挿絵風に撮る／描く）、灰色のフォークのピン（種類の絵に）、空っぽの画面のポコタン、スタンプの絵。
- Claude は、決まりの見本 1 枚・1 枚ずつの指示文・届いた絵の仕上げ（色味・輪郭・背景抜き）・実寸の比較を用意する。質の低い絵は入れない。

### 3.7 文の調子
- ポコタンのセリフ（文字）は、ごほうび・空の画面などに入れてよい。**音の声は追加しない**（2026-11-23 オーナー）。ほかの画面の文は短く・やさしく・具体的に。
- 作り手の言葉をやめる: 「地図のデータのお店」→「まだ情報が少ないお店」、「EXP」→「けいけん」、「記録のかぎ」→言い換え。ボタンは押すと何が起きるかを書く。
- 「！」と記号を減らす。1 画面 1 つの伝えたいこと。

## 4. 画面ごとの作り直し（順番）
1. **土台**: 色・字体・形・影・余白の決まりを CSS の変数にし、部品を作る（見た目はまだ変えない所から）。
2. **地図の上とごほうび**（毎回見る所）: チェックインのスタンプ演出、お店のシート（下半分の空白を「わたしの記録」「みんなの感想」「近くの同じ種類」で埋める）、ピンとまとめの丸・札の整理、メニューの扇の下に薄い幕。
3. **集める画面**: 図鑑（紫をやめ、まだのカードは「霧の中のシルエット」で 1 枚ずつ違う形）、記録（空の状態の不具合を直し、手帳の 1 ページに）、実績、気配・ミッション（紫をやめる）。
4. **入口と設定**: ログイン、初回設定（ゲームの絵の画面に）、設定・マイページ（手帳の目次風に。緑のスイッチをやめる）、お問い合わせ・規約。
5. **絵の差し替え**: 画風の決まりに沿って、届いた絵から順に。

各段は、変える前後の画面を同じ手順で撮って比べ、テスト役のレビューを通してから dev に出す（今日から使っている手順）。

### 画面の作りが 3 種類ある
1. **ゲームの絵の作り**（ログインボーナス・地図の上のボタン・キャラ一覧）← いちばん良い
2. **太い輪郭の漫画の作り**（図鑑・感想を書く）← 元気で可愛いが、1 とも 3 とも違う
3. **Web の作り**（設定・記録・初回設定・プレゼント・マイページ・お問い合わせ）← 安っぽさの元
→ 1 を芯に、2 の良い所（リボンの見出し・丸ゴシック・ぷっくりした影）を取り込み、3 を全部作り直す。

## 8. 「可愛い・綺麗・センスが高い」を UI のルールにしたもの（2026-11-23。オーナー「具体的に認識してほしい」）
| 言葉 | UI として具体的にやること |
|---|---|
| 可愛い | 角は大きく丸く、物はぷっくり（上に小さな光・下にうすい影）。色はやさしいパステル（鮮やかすぎない・白に寄せる）。押すと少し弾む。きらめき・ハートは一画面に 1〜2 個まで |
| 綺麗 | 余白は 8 の倍数。線の太さと影は全部同じ決まり。色の数をしぼる。絵は高解像度。文字の大きさの段は 1.25 倍以上離して強弱をはっきり |
| センスが高い | 飾りは 1 か所に集中し、ほかは引き算。その画面だけの「看板の一点」。素材感（紙・プラスチック・金箔）を混ぜずにそろえる。細部（押したとき・空のとき・初めて手に入れたとき）まで作り込む |

質が低く見える原因（見本を作って分かったこと）: 小さいアイコンをそのまま大きく使う（単純さが目立つ）／同じ形が並ぶだけで山場がない／質感と光が無い／一色（茶色）が強すぎて差し色が効かない／集めている感（数・レア・次）が見えない。

## 9. 見やすさの決まり（2026-11-23 オーナー「見やすさを落としたらダメ」）
- 読ませる文字は 12px 以上、お店の名前は 14px 以上（10px は数字の札だけ）
- 文字と背景の明るさの差は 4.5 : 1 以上（WCAG AA）
- 押す所は 44px 四方以上
- 文字の上や背景に模様・光を重ねない（飾りは文字から離す）
- 1 画面で一番大事なものがひと目で分かる

図鑑の 4 案（https://claude.ai/artifact/B6edgjs24CsHAgw9QEpPmt）の見やすさ: A ショーケース ×（暗い地・名札 10px）／B ホロカード ○／C 黒板 △（補足が小さく差が弱い）／D 絵本の街 △（名札 9px。大きくすれば直る）。

## 10. カード・棚の主役の絵（2026-11-23 オーナー「ホットペッパーの画像を一部使える前提が抜けていた」）
主役の絵は次の順で出す: ① 自分が感想で撮った写真 → ② ホットペッパーの公式の写真（`shops.photo_url`。図鑑のデータの `photoUrl` に入っている。ZukanDetail ではすでに「公式の写真」として表示）→ ③ お店の模型の絵（地図のデータだけのお店 `osm:` など写真が無いとき）。
写真を出す所には、ホットペッパーの写真と分かる小さな表示を付ける（今のお店のシートと同じ）。同じ種類でもカードごとに絵が違い、「本物の店を集めている」感が出る。

## 11. 守ること（2026-11-23 オーナー。図鑑の見本 5 つへの答え）
- 図鑑の見本（シール帳・カードバインダー・4 案・B×D）は、**どれも今より見やすさ・使いやすさが劣り、AI っぽさも変わらなかった**。
  - 劣った所: 今の図鑑は「何軒中何軒・どれが未発見か」がひと目で分かる。見本は建物や伏せたカードを押さないと中身が分からず、手間が増えた。
  - AI っぽいまま: グラデーション・ホロ・傾けたカード・きらめきなど、よくある飾りを足しただけで、作り手の判断がこもった細部が無い。
- **雰囲気は今のもの（クリーム色と茶色の手帳・手描き風の塗りの絵・ログインボーナスの世界）で統一し、崩さない。** 新しい世界観は作らない。
- **使いやすさは今より落とさないことが条件。** 見本は、今の画面と同じ情報がひと目で分かるかを先に確かめてから見た目を上げる。
- 質を上げる方法は Claude の考えだけでなく、調べて根拠をそろえる（再調査中）。

## 12. 紫は「謎」の色として残す（2026-11-23 オーナー「まだ紫の方がいい。何を持って青にしたのか」）
- 紫は、図鑑のまだのお店と今日の気配（謎の気配）で「謎・まだ分からない」の意味に使われている、役割のある色。**消す対象ではない**。
- Claude は根拠なく「ほかに無い色＝外れた色」と決めつけ、霧の青に変えた（図鑑の仕上げの試し）。見比べて紫のほうが良いと判断されたので、図鑑は本番の見た目に戻した。
- 2 章の「やめる色」から紫を外す。色を変えるときは、その色が何の意味で使われているかを先に調べ、変える理由をオーナーに示してから。

## 13. 図鑑の仕上げの試し 2 回目も、本番より悪かった（2026-11-24 オーナー「余計悪くなってない？」）
- 本番の図鑑は「太い濃い輪郭＋ずらした固い影」の、元気でくっきりした作り（案 B としてオーナーが選んだ。図鑑の個性）。
- Claude は「影は重ねてやわらかく・輪郭は温かいこげ茶・塗りに明暗」を当てはめた。調べた技術は本物らしさを出す画面向けで、くっきりした作りに混ぜると輪郭と影が弱まり、ぼやけて締まりがなくなった。図鑑は本番の見た目に戻した。
- 学び: 技術が正しくても、その画面の作り（くっきり・漫画的か、やわらかい・本物らしいか）に合うかを先に確かめる。本番の良さを弱める方向の「仕上げ」はしない。

## 14. ログインボーナスを手本にしない（2026-11-24 オーナー「ログインボーナスは生成した絵なのだから参考にするのが間違い」）
- ログインボーナスの枠は画像生成で作った絵。手本にすると AI っぽさごと写す。「いちばん良い画面」は Claude の判断で、オーナーの判断ではなかった。
- これまでの資料のうち「ログインボーナスを基準・お手本・芯にする」「ログインボーナスの色・輪郭を測って合わせる」とした所（1 章・3 章・6 章・docs/uiux/2026-11-23-css-craft-research.md の「アプリ内の基準」・2026-11-23-quality-research-2.md の手順 1・3・12）は無効。
- 手本は、人が作った質の高い実在のアプリにする。生成した絵（ログインボーナス・タイトルなど）は手本にしない。
