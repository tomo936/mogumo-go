# 初回設定（ニックネーム・最初のキャラ・自宅）設計

日付: 2026-11-06 ／ 承認: 本人（流れと方式 A）／ 対応: SPEC S13・S15・S6・§8、基本設計 2.1・2.2・3.1・N-01、DB 詳細設計 3.2（profiles）・D-05・D-09

## 目的と理由
初めてログインした人が、ニックネーム・最初のキャラ・自宅の位置を決めてから地図に入れるようにする。自宅は霧・クエスト・記録の起点で、PLAN 4（お店・霧）の前に要る。記録の開始時点もここで決まる（S6）。

## ゴール
- 流れ（本人承認）: ① ニックネーム → ② 最初のキャラ → ③ 自宅の位置 → 地図
- **1画面ずつ別の画面**（N-01 の答え）。URL は `/setup/name`・`/setup/character`・`/setup/home`（方式 A）。戻るボタンと iPhone のスワイプで前の画面へ戻れる
- 途中の入力（ニックネーム・選んだキャラ）は端末の一時保存（sessionStorage）に残し、リロードしても続きから
- ① ニックネーム: 1〜10文字（Unicode のコードポイント数、D-05）、空白だけは不可、重複可。入力欄の下に「あと◯文字」
- ② 最初のキャラ: シロの立ち絵2枚（`src/assets/characters/starter-boy.webp`・`starter-girl.webp`）をカードで並べて1つ選ぶ。**ID は 101＝男の子、102＝女の子**（D-09 の未決定をここで決める）
- ③ 自宅: 地図の中央に家の印を固定し、地図を指で動かして位置を合わせる。「現在地へ」ボタンで現在地に戻る（最初は現在地から始める）。「ここを自宅にする」で確定
- ③ の確定時に、サーバーの profiles に `nickname` と `starter_character_id` を1行作る（＝初回設定の完了、記録の開始時点）。成功したら自宅の位置を端末に保存して地図へ
- 自宅の位置は **端末の中（localStorage）だけ**。サーバー・ログ・外部には送らない（SPEC §2.5・基本設計 3.1・DB D-07 の原則）
- 振り分け:
  - ログイン済みで profiles の行が無い → `/setup/name`
  - profiles はあるが端末に自宅が無い（機種変更・データ消去） → `/setup/home` だけ（このときはサーバーに何も書かない）
  - 両方そろっている → 地図
  - 初回設定が終わった人が `/setup/*` を開いたら地図へ

## チェック役の質問への本人の答え（2026-11-06）
- **自宅の保存はアカウントごと、ログアウトしても消さない**: 端末保存のキーに user_id を含める。別のアカウントには前の人の自宅を見せず使わない（その人は自分の自宅を設定する）。前の人のデータは端末に残るがアプリからは見えない
- **③で現在地が取れないときは先に進めない**: 地図の画面と同じ案内（拒否なら iPhone の設定の直し方と「再読み込み」、見つからないなら「もう一度試す」）を出す。決まった場所から開く逃げ道は作らない
- ③の地図はアカウント内の決まり（中心固定）を外した「指で動かせる地図」。現在地は最初に1回取ってその場所から始め、追いかけ続けない（リーダーの判断）

## やらないこと（非ゴール）
- マイページでの変更（ニックネーム・自宅の変更）。PLAN 5
- 地図上のアバター表示と歩行アニメ（3b。今回の絵はカードにだけ使う）
- 霧・お店・ルート（PLAN 4）

## 失敗とみなすこと（アンチゴール）
- 自宅の座標が端末の外に出る（サーバーへの送信、URL、ログ、エラー報告）
- profiles の作成に失敗したのに地図へ進んでしまう、または入力が消える
- 途中でリロード・スワイプしただけで最初からやり直しになる

## 制約
- クリーンアーキテクチャの決まり（CLAUDE.md）: `src/setup/domain/`（ニックネームの判定、自宅の値の検査、振り分けの判断）、`src/setup/infra/`（profiles の読み書き、端末保存）、`src/setup/ui/`（3画面）
- profiles の権限: authenticated は `nickname`・`starter_character_id` の列だけ INSERT／UPDATE できる（0001_init.sql）。RLS で自分の行だけ
- 開発中は開発用の Supabase を使う（`.env.local`）
- 地図の部品は `src/map/` のものを使う。③ では「自分が中心に固定」のルールを外し、指で動かせる地図にする（自宅を合わせる画面だけの例外）

## 方式の比較（画面のつなぎ方）
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）画面ごとに URL** | `/setup/name` など3つの URL | スワイプで戻れる。リロードで続きから | コードが少し増える |
| B 1画面の中で切り替え | 中身だけ切り替える | 最も簡単 | スワイプで初回設定ごと抜ける。リロードで最初から |
| C 地図の上にポップアップ | 地図の上で順に設定 | 地図を見ながら設定できる | 自宅合わせでの地図の移動が「中心固定」とぶつかる |

本人が A を承認（2026-11-06）。
