# 実装ステップ1「土台作り」設計（短い設計メモ）

日付: 2026-11-05 ／ 承認: 本人（方式 A）／ 対応: PLAN-cycle1「積む順番」1〜2、基本設計 2.1〜2.3、N-01（ログインのみ）・N-12（ルーティング）

## 目的と理由
本物の Supabase で Google ログインし、ログイン後の画面に入れるところまでを動かす。あわせて画面切り替え・テストの仕組みを入れ、Vercel でスマホから開けるようにする。以後の地図・霧・お店などを載せる土台にする。

## やること（ゴール）
- ログイン画面（Google でログイン）→ 仮の初回設定画面 → 仮の地図画面（ログアウトボタン付き）
- ログイン状態は Supabase Auth から受け取り、未ログインで保護された画面を開くとログイン画面へ戻す
- テスト基盤（Vitest＋Testing Library）。最初のテストは「未ログインならログイン画面へ戻る」
- Vercel 配信（画面の URL を直接開いても動く SPA 設定）

## やらないこと（非ゴール）
- 地図の表示（ステップ3）、自宅設定・ニックネーム・最初のキャラ選択の本実装（地図が要るため。仮画面のみ）
- profiles 行の作成（初回設定の本実装と一緒に行う）
- 世界観に合わせた本格的な見た目（最低限の白基調でよい）。画像素材は使わない（必要になったらシロへ依頼）

## 失敗とみなすこと（アンチゴール）
- キー（service_role、Google のクライアント シークレット）がソースやバンドルに入る
- ログインしていないのに保護画面の中身が見える

## 制約
- CLAUDE.md のツールチェーン（import type、拡張子付き import、enum 不可、noUnused*、Oxlint）
- ブラウザが使うのは `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY`（公開してよいキー）だけ
- Google のクライアント シークレットは Supabase の管理画面にのみ置く（設定済み）

## 方式の比較
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）React Router** | 画面ごとに URL。地図を共通の土台（レイアウト）にして各画面を重ねる | iPhone のスワイプ戻る・リロードが自然に動く。将来の地図常駐と相性が良い | ライブラリが1つ増える |
| B 自前の状態切り替え | 表示中の画面を変数で持つ | 最も簡単 | 戻る操作でアプリごと閉じる。リロードで最初に戻る |
| C TanStack Router | 型安全なルーター | 型が強い | 6画面には大げさ |

本人が A を選択（2026-11-05）。

## 決まっていること
- 画面の URL（仮）: `/login`（ログイン）、`/setup`（仮の初回設定）、`/`（仮の地図）
- Google ログインは Supabase Auth の OAuth（リダイレクト方式）。戻り先は Site URL（開発: `http://localhost:5173`）
- Vercel の管理画面での接続と環境変数の登録は本人が行う。Vercel の URL は Supabase の Redirect URLs と Google の JavaScript 生成元に追加する

## 作る人に任せること（シロ・リーダーの判断として記録）
- React Router の使い方（library mode を想定）、ファイル配置、ログイン状態の持ち方（小さな Context か hook）
- テストでの Supabase の差し替え方法
- `/setup` へ行くか `/` へ行くかの判定は、今回は「常に `/` へ。`/setup` は手で開ける仮画面」でよい（profiles 未作成のため）
