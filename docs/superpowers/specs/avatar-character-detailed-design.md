# 3D アバター 詳細設計書（作る人が、このとおりに手を動かすための数値と手順）

- 版: 0.95（2026-11-12、Fable。独立の点検とオーナーの指摘を反映）。方針と流れは `avatar-character-pipeline.md`（以下「方針書」）。この文書は、その各段の**中身（数値・計算の仕方・設定・ファイルの形）**。
- 数値の出どころ: 「実績」＝男の子の今の台本（`art/prototypes/avatar/blender-v2.py`・`blender-finish.py`・`anim2-page.ts.txt`）で使って、動きや顔が良いと確認できた値。「案」＝ A ポーズの流れでは未検証。男の子 1 体目で確かめて、実績に書きかえる。
- 長さの単位は、**身長を 1.0 とした割合**（どのキャラも身長 1.0 にそろえる）。角度はラジアン（かっこ内に度）。

## D1. 座標・名前の決まり（全キャラ共通）
| 項目 | 決まり |
|---|---|
| 向き | 上が +Z、キャラの前が −Y、キャラの左手が +X（Blender の中）。GLB に書き出すと、上 +Y・前 +Z になる |
| 大きさ | 足の裏が Z=0、頭のてっぺんが Z=1.0。左右のまん中が X=0 |
| 物の名前 | 形 `avatar`、骨組み `rig`、材質 `avatar`（体）と `face`（顔） |
| 骨の名前 | `hips`・`chest`・`head`・`upperarmL/R`・`forearmL/R`・`thighL/R`・`shinL/R`・`footL/R`・`pack`（L はキャラの左＝+X） |
| 動きの名前 | `walk`・`run`・`idle`・`joy` |
| ファイル | `art/characters/<名前>/` に、`config.json`（D13）・途中の物・`avatar.glb`・`avatar-lod.glb`・検査の画像と動画。アプリ用は `src/assets/characters/<id>/` へ写す |

## D2. 絵の準備（段 0 → 段 1 の入力）
- 台本: `split-sheet.py <三面図> <出力の接頭辞>`。
- 背景の決め方: 「明るさの最小 > 225 かつ 色の幅 < 22」の画素で、絵のふちからつながっている所。床の影がある絵は「最小 > 196 かつ 幅 < 20」も背景にする。
- 切り分け: 3 体それぞれの体のまん中の点から、背景でない所をたどって 1 体ぶんを取り出す。**3 体の範囲が重ならないことを出力で確かめる**（重なったら、絵の間が足りない → 段 0 へ）。
- 1 体ごとに、長い辺の 1.15 倍の正方形のまん中に置き、1024×1024 の透明 PNG にする。
- できる物: `<接頭辞>-front-rgba.png`・`-side-rgba.png`（右向き）・`-back-rgba.png`。

## D3. 形と色の生成（段 1）
| 項目 | 値（実績: 腕を付けた絵で 243 秒・VRAM 4.4GB） |
|---|---|
| 道具 | ComfyUI＋ComfyUI-Hunyuan3DWrapper、ノード `Hy3DGenerateMeshMultiView` |
| モデル | `hunyuan3d-dit-v2-mv-fp16.safetensors` |
| 入力 | front・back・right（真横の絵は右向きなので right。left に入れない） |
| 手数・種 | 50 手。seed は 123・456・789 の 3 つを、1 回の実行で続けて回す（約 12 分） |
| 面の数 | 生成の中で 3 万に減らしてから、色を塗らせる（`Hy3DPostprocessMesh` の `max_facenum = 30000`） |
| 色づけの元の絵 | 台本を読むかぎり、色づけ（`Hy3DSampleMultiView` の `ref_image`）は**正面の絵 1 枚**だけを見ている（未確認）。後ろ・横の色は AI の想像になるので、関門 2 で後ろ・横の色を必ず絵と比べる |
| 出力 | `ComfyUI/output/mogumo/<名前>_<ラベル>_shape_*.glb`（約 5 万三角形）・`_textured_*.glb`（絵 2048²）・`_views_*.png` |
| 起動 | `--disable-pinned-memory`、`127.0.0.1:8188`。古い ComfyUI が残っていると拒否される（ポートの取り合い） |
- オーナーへは、写す 2 行＋実行 1 行の PowerShell を、そのまま貼れる形で渡す。

## D4. 関門 1 の測り方（段 1 の確認。台本 `gate1-probe.py` を男の子で作る・案）
1. **腕が離れているか**: 高さ Z を 0.01 きざみで輪切りにし、各輪切りで、三角形のつながりから島の数を数える。合格の形: **わきの点**（腕と胴の間の背景が終わる一番上の点。輪切りを下から上へ見て、腕の島が胴につながる最初の高さ）より下では、**胴の島と、左右の腕の島が別**（島 3 つ）。わきの点の高さが、絵のわきの高さと ±0.03 で合う。
2. **足が離れているか**: 股より下で、左右の足が別の島（島 2 つ）。
3. **内側の色**: 腕の島の面のうち、法線が胴の方を向く面（X 方向の成分が −0.5 より内向き）について、絵の色を数える。袖の高さでは服の色が面積の 90% 以上、手の高さでは肌の色が 90% 以上。色の分け方は `config.json` の色の表（D13）で、色相・あざやかさ・明るさの範囲で決める。
4. **首のまわり**: 首の高さの前後で、頭（あご・後ろ髪）と胴（肩・背中・フード）が、首の柱以外でつながっていないか（輪切りの島で見る）。
5. **輪かく**: 形を正面・右横から影にして、絵の影と重ね、重ならない所の割合（5% 以内。案）。横の絵の向き（right）が合っているかも、ここで分かる。
6. **そのほか**: 左右の差（X を返して重ねたときの体積の差 10% 以内）、ちぎれた小片（面積 0.5% 未満の島）が無い、身長に対する頭の高さが絵と ±5%。
7. **画像**: 正面・右横・後ろ・斜め上（上から 40°）の 4 枚を、三面図と並べる。リーダーが見る。

## D5. 形と色を整える（段 2）
| 手順 | 中身 |
|---|---|
| 1. 向きと大きさ | D1 に合わせる（回す・足の裏を 0・身長 1.0） |
| 2. 掃除 | 重なった点をまとめる（0.0005）、ちぎれた小片を消す、法線を外向きに |
| 3. 減らす | **Blender では減らさない**（生成の時点で 3 万。D3）。色を塗った後に減らすと、絵の継ぎ目に線が出る |
| 4. 区分け | 面を「肌・髪・服の上・服の下・靴・持ち物・顔」に分ける。色（D13 の色の表）と場所（高さ・前後）で決め、小さな飛び地は周りに合わせる |
| 5. 色の直し（関門 2 で落ちたときだけ） | 区分けごとに: ①細かいノイズをならす（絵の上で、同じ区分けの中だけをぼかす）②色を参考の絵の色に合わせる（区分けの平均の色を、参考の同じ所の平均へ移す。明暗の差は残す）③区分けの境目のにじみを、境目から 3 画素ぶん塗り直す。**形に無い模様を描かない** |
| 6. 軽い版 | 作らない（切り替えで輪かくが変わる。実機で重いと測れてから考える） |
- 絵は 2048×2048 を 1 枚（体）。書き出しは PNG のまま GLB に入れる（今の実績 1.8MB）。2MB を超えたら 1024² にして、見た目を比べる。

## D6. 骨の位置の決め方（段 3）
骨の位置は、形から**目印**を測って決める（キャラごとに `config.json` に記録）。かっこ内は男の子の実績（腕を付けた形のとき）。
| 目印 | 決め方 | 男の子 |
|---|---|---|
| 股の高さ HIP | 両足が 1 つにつながる高さ | 0.25 |
| 腰の上 WAIST | 股と首の、下から 1/3 | 0.37 |
| 首 NECK | 頭と胴の間で、輪切りが一番細い高さ | 0.545 |
| 体の前後のまん中 TY | 胴の輪切りの重心の Y | −0.04 |
| 肩 | 腕の島が胴につながる帯のまん中 | (±0.135, −0.03, 0.49) |
| ひじ・手首 | **腕の島の軸**（点の集まりの一番長い向き）の上で、肩から 45%・92% の所（案。男の子の実績の比） | — |
| 足のつけ根・ひざ・足首 | 足の島の軸の上。つけ根は HIP、ひざは HIP と足首のまん中より少し上（58%）、足首は靴の上のふち | X ±0.068、ひざ 0.145、足首 0.03〜0.045 |
| 足先 | 足首から靴の先へ | (±0.068, −0.02, 0.045) → (±0.068, −0.11, 0.02) |
| 持ち物 | 持ち物の区分けの上のふち（背中側）から下へ | (0, 0.09, 0.50) → (0, 0.11, 0.30) |

骨のつながり: `hips` →（`chest` →（`head`、`upperarmL/R` → `forearmL/R`、`pack`）、`thighL/R` → `shinL/R` → `footL/R`）。
- 骨を入れるのは A ポーズの形のまま。腕の骨は、開いた腕の軸に沿って置く。

## D7. 重みの付け方（段 3）
1. Blender の自動の重み（熱の広がり方式）を付ける。失敗（点に重みが付かない）したら、近い骨までの距離で付ける。
2. 上書き（この順）。`sstep` はなめらかな 0→1。
| 所 | 決まり | 男の子の実績 |
|---|---|---|
| 頭 | **頭・髪・耳の区分け**の点は `head` 100%（高さだけで切らない）。首の柱の帯（上下 0.03）だけ、胸となめらかに混ぜる | 男の子は髪が短いので、Z 0.72〜0.78 で 0→100% でも同じ結果 |
| 持ち物 | 持ち物の区分けの面は `pack` 100%。ベルト・ひもは `chest` 100% | Y>0.075、Z 0.225〜0.53 |
| 靴 | 靴の区分けは `foot` 100%。足首の帯 0.03 だけ `shin` と混ぜる | Z<0.09 |
| 関節 | 肩・ひじ・股・ひざ・足首は、**自動の重みのまま**（上書きしない）。試しの姿勢で折り重なり・とがりが出た関節だけ直す。直すときの帯の幅は「その関節の半径 × 使う最大の角度 × 1.2 以上」（内側の面は 半径 × 角度 だけ縮むので、それより狭い帯だと面が折り重なる） | 男の子の足は自動の重みで問題なし |
| 肩のまわり | 腕の島の点は腕の骨、胴の島の点は胸。混ぜるのは D4 で測った「肩の帯」だけ | — |
3. 仕上げ: 1 点あたり骨は 4 本まで、合計 1.0 にそろえる。重み 0 の点が 0 個であることを数える。
4. 確かめる数字: 頭・持ち物・靴の区分けで、決めた骨が 100% でない点が 0 個。

## D8. 顔（段 4）
| 項目 | 決まり（実績） |
|---|---|
| 顔の面 | 頭の前の面のうち、顔の区分け（髪・耳をふくまない）。材質 `face` を割り当てる（体と同じ形の一部。別の板にしない） |
| 絵の形 | 横に 4 こま並べた 1 枚。こまの順は 0 ふつう・1 半分とじ・2 とじ・3 うれしい。男の子は 1932×290（1 こま 483×290） |
| 絵の貼り方 | 顔の面を前から平らに写す。`u = ((x − FX0) / (FX1 − FX0)) / 4`、`v = (z − FZ0) / (FZ1 − FZ0)`（FX0〜FX1・FZ0〜FZ1 は顔の面の左右・上下の端） |
| こまの中身 | こま 0 は、体の絵の顔の所をそのまま写す。こま 1〜3 は、こま 0 を写してから、**目・まゆ・口の枠の中だけ**を描きかえる。枠の外は 1 画素も変えない（画素の差を数えて 0 を確かめる） |
| 目・口の枠 | `config.json` に、こまの中の位置（左目・右目・口の四角）を書く |
| 材質 | 粗さ 0.9、絵の拡大は Linear、透明は使わない |
| 切り替え | 画面側で `face` の絵の `offset.x = こま / 4`（`repeat.x` は 1 のまま。貼り方の式で 1/4 にしてある） |
| まばたき | 画面側。0→1（0.04 秒）→2（0.07 秒）→1（0.04 秒）→0。間隔は 2〜6 秒の乱数。うれしいの間はしない |

## D9. 動き（段 5）
- **立ち姿（動きの土台）は、元の立ち絵に合わせる。** 三面図の姿勢（腕・足を開く）は形を作るための姿勢で、動きの土台にしない。腕も足も、元の立ち絵の開きまで戻してから、動きを足す（男の子 1 体目で、足を戻し忘れて、歩き・走りが足を開いたままになった）。三面図は、足は元の立ち絵に近い幅（ほぼそろえる、ただし足どうしは離す）で描かせると、戻す量が小さく安全。
- 30 コマ/秒。決めた値を、周期のあるなめらかな 3 次の曲線（Catmull-Rom）でつなぎ、毎コマを GLB に焼く。
- **立ち姿の腕**: A ポーズから腕を下ろす角度 `armDown`（案: 開き 0.52（30°）の絵なら、0.30〜0.35 下ろして、体から 0.17〜0.26（10〜15°）開いた所で止める）を、4 つの動き全部の土台に足す。
| 動き | コマ数（秒） | 主な値（男の子の実績。体つきで変えるのは ★） |
|---|---|---|
| walk | 30（1.0） | 腕の振り ±0.28★、ひじ 0.32±0.12、腰のひねり ±0.10、胸の逆ひねり ±0.17、頭は腰＋胸の逆へ 0.8 倍、腰の左右の傾き ±0.035、胸の傾き ±0.05、前傾 0.05、頭のうなずき −0.04±0.025（体の上下から 0.05 秒おくれ）、持ち物の揺れ ±0.04、歩幅★・足の上げ★ |
| run | 18（0.6） | 腕の振り ±0.5★、ひじ 1.45±0.12（約 85°）、前傾 0.22＋胸 0.04、腰のひねり ±0.12、胸 ±0.20、ひざの曲げ最大 1.95★（関門 3 の上限の 8 割を超えるなら下げ、体のはずみで走りを見せる）、両足が浮く時間が 1 周に 2 回、持ち物の揺れ 0.05±0.08 |
| idle | 90（3.0） | 呼吸: 胸の横と前後を 1.5% ふくらませる（頭は逆に戻して大きさを保つ）、胸の傾き −0.012、頭 −0.01+0.012、腕の開き 0.03+0.02 |
| joy | 24（0.8） | 腕を開く 0.55±0.15、頭 −0.1、小さくはねる |
- 足を地面に着ける: 各コマで、両足の骨（足首と足先）の一番低い所が Z=0 になるよう、`hips` の高さを決める（浮く動きは、その上に高さを足す）。
- つなぎ目: 0 コマ目と最後の次のコマが同じ値・同じ速さ（曲線が周期なので自動。書き出した GLB で差を数えて確かめる）。
- **上の表は男の子の値。ほかのキャラへそのまま写さない**（方針書 原則 5）。キャラごとに: ①関門 3 で、各関節の破れない上限を測る ②動きの角度は上限の 8 割まで ③歩幅 = 足の長さ × 0.9（歩き）・× 1.3（走り）（案）④腕が胴・持ち物にめりこまないよう、腕の開きを足す ⑤そのキャラで段 6 の検査を全部やる。
- 持ち物の揺れは 0 を基本にする（表の値は、男の子の今の形のもの。A ポーズの形で境目に段が出ないと確かめたら使う）。
- 型が違うキャラ（四本足・手足なし・しっぽや羽）は、動きの表を一から作る。

## D10. 書き出し（GLB）
- Blender の glTF 書き出し: `export_format='GLB'`、`export_apply=False`、法線・UV・皮（skins）あり、動きは `NLA_TRACKS`（動き 1 つが 1 本）、`export_force_sampling=True`。
- 中身の決まり: 形 1 つ（材質 2 つ）、骨 14 本前後、動き 4 つ（名前は D1）、絵 2 枚（体・顔）。
- 目標: 2MB 以内、3 万三角形前後。軽い版は作らない。
- 書き出した GLB を読み直して数える: 三角形・骨・動きの名前と長さ・材質の名前・重み 0 の点。

## D11. 撮影と検査の設定（段 6）
| 項目 | 値（実績は `anim2-page.ts.txt`・`cap2.mjs.txt`） |
|---|---|
| 明かり | 半球の光（空 `#ffffff`・地面 `#e6dccf`・強さ 2.2）＋太陽（`#fff2e4`・強さ 2.4・位置 (−0.6, 0.8, 0.55)）。絵の色は sRGB、`anisotropy = 8` |
| 背景 | 白（線・すき間用）と、地図に近いクリーム `#fbf0d9`（なじみ用）の 2 通り |
| カメラ（6 方向） | 高さは体のまん中。正面 0°・右横 90°・後ろ 180°・左横 270°（見下ろし 0°）、斜め上の前 30°・斜め上の後ろ 150°（見下ろし 40°＝地図の見え方）。体が画面の高さの 8 割 |
| コマ | 各動きの 1 周を 8 等分。加えて、腕が一番前・一番後ろのコマ（動きの値から求める） |
| 並べ画像 | 1 つの動きにつき、6 方向 × 8 コマ ＝ 48 枚を 1 枚に並べる（1 枚 300px）。4 つの動きで 4 枚 |
| 動画 | 斜め上の前から、4 つの動きを順に。30 コマ/秒、H.264・yuv420p、高さ 600px。実際の大きさ（40px・16px）は 4 倍に拡大して並べる |
| 数える物 | ①背景が体の穴から見える点（6 方向 × 全コマ。0）②動く部分の内側の色（D4-3）③重み（D7-4）④足の裏の最小の高さ（0±0.002）⑤つなぎ目の差（0）⑥隣のコマとの輪郭の差が急に大きいコマ（ちらつきの手がかり） |
| 見る人 | 作った担当が全部見る → リーダーが全部見る → オーナーへ（動画＋並べ画像 1〜2 枚） |
- 画像は見る枚数が多いので、並べ画像にまとめて、見る回数を 1 つの動きにつき 1 回にする（使用量のため）。

## D12. アプリとの約束（段 7 の入口。実装の計画は別の文書）
- 読む: `GLTFLoader`。動きは `AnimationMixer` で名前で再生。切り替えは 0.25 秒かけて混ぜる。
- 顔: `face` の材質の絵の `offset.x = こま / 4`。窓口は `avatar.express('normal' | 'happy')`、まばたきは中で自動。
- 大きさ: 地図の上で約 20m、画面で最小 16px。軽い版への切り替えはしない。
- 更新: 30 コマ/秒（待機でも落とさない）。
- 歩く速さ: 動きの再生の速さ = 進む速さ ÷（歩幅 × 2 ÷ 周期）。待機・歩き・走りの切り替えは、速さが約 1 秒続いてから（行ったり来たりを防ぐ）。
- 明かり: D11 と同じ色と強さに合わせる（お店の模型となじむか、アプリの画面で比べる）。
