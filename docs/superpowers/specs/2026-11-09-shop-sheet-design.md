# お店のシート（2段・写真シール＋自分の記録）設計メモ

- 日付: 2026-11-09
- 決定: オーナー（案A〜C を見て「模型は種類ごとに同じで普通」→ 写真シール＋自分の記録（1＋3）→ ラフ D を見て「これでいこう」。詳細で出す内容はリーダーに任せる）
- ラフ: `art/reference/ui/shop-sheet-D.png`（配置の正本。見た目の仕上げはミシェーラ）

## 意図
お店をタップしたときのシート（SPEC S17 の「お店詳細」を兼ねる）を、**そのお店だけのもの**に見せる。模型は種類ごとに同じなので主役にしない。お店ごとに違うのは「本物の写真」と「自分とそのお店の記録」なので、この2つを主役にする。あとで図鑑のカード詳細（S11）から同じ画面を開けるようにする。

## 考えた作り方（Approaches）
- A 写真が主役: 写真の無いお店（地図データだけ）で上が空く。
- B 模型が主役: もぐもGOらしいが、同じ種類の店はどこも同じ見た目（オーナー「普通」）。
- C 記録が主役: 図鑑とつながるが、まだ行っていない店では中身が薄い。
- **採用: A＋C**。写真をシール（ポラロイド＋マスキングテープ）で出し、写真の無い店は同じ枠に種類の模型の絵を入れる。下に「わたしの記録」。

## 決めたこと
### 2段のシート
- ① タップで小さいシート（今の位置）。上にスライドで ② 全画面。全画面で下にスライド／× で ① に戻る。① で下にスライド／× で閉じる。半分の段は作らない（2026-11-06 の将来案どおり）。
- 地図の操作・カメラの動きは今のまま（道路をタップしても何もしない、も変えない）。

### ① 小さいシート
小さな写真シール（無い店は種類のピンの絵）・店名・種類・予算・ここからの距離・「○回行った」（0回なら出さない）・チェックインのボタン・「上にスライドでくわしく」。気配の伏せ・+10 の札・エラー文は今のまま。

### ② 全画面
1. 写真シール。下の余白に「YYYY.M.D はじめて」（行っていなければ「まだ行ってない」）。
2. 店名、札（種類・予算・営業中/時間）、お店のひと言（ホットペッパーの catch）、ここからの距離。
3. 「わたしの記録」: 行った回数・はじめて行った日・この前行った日。通うと枠が変わる: **1〜2回 ふつう／3〜9回 銀／10回〜 金**。次の枠までのバー（「あと1回で銀の枠」）。0回なら「まだ行っていません。チェックインで +30」。
4. チェックインのボタン、「ホットペッパーで見る ›」、「Powered by ホットペッパーグルメ」。
- 地図データだけの店: 写真の代わりに種類の模型の絵、「くわしい情報はまだありません」、ホットペッパーの欄は出さない。

### データ
- 写真: Edge Function `shops-hotpepper` は既に `photo_url`（mobile の l）を返している。アプリ側（`src/shops/infra/hotpepper.ts`）で `ShopDetails.photoUrl` として受け取る。合体した店もそのまま持つ。
- ホットペッパーのページ: **リーダーの判断**で、店の ID から `https://www.hotpepper.jp/str<ID>/` を作る（サーバーと DB を変えずに済むため）。外のタブで開く。
- 記録: `checkins`（RLS で自分の行だけ読める）から、その店の `shop_id`（合体した店は `mapId` の osm: も）を読み、回数・最初・最後の日を出す（日本時間）。シートを開いたときに読む。読めなければ記録の欄を出さない。チェックインが通ったら、その場で数を足す。
- 枠の段の計算は `src/checkin/domain/` の純粋な関数（テストする）。

### 気配の店（伏せている間）
写真・店名・ひと言・ホットペッパーの欄は出さない（写真で正体が分かるため）。シールの枠には「？」の絵（mystery の模型の絵）、ヒントの行は今のまま。

## しないこと
- 自分の写真・感想・星（S12・S14。図鑑と感想の段で）。
- 模型を回す表示、お店ごとの模型（看板に店名など）。
- 図鑑の画面そのもの（次の段）。

## 素材（ミシェーラに依頼）
ポラロイドの枠（ふつう・銀・金）、マスキングテープ、写真の無い店のシール用の絵の背景。依頼: `handoff/to-shiro/2026-11-09-shop-sheet-art.md`。届くまでは CSS の仮の見た目で作る。

## 実装で任せること
シートのスライドの細かな手ざわり（どれだけ引いたら段が変わるか）、CSS の細部、記録を読むクエリの形。
