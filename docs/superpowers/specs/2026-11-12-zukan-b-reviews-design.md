# 図鑑の作り直し（案B コレクションカード）＋感想と写真 設計（2026-11-12）

状態: オーナー承認済み（2026-11-12「いいよ」。同時に「感想は公開・非公開を選べるように」を追加）

## 目的
- 図鑑が「全体的に安っぽい」（オーナー 2026-11-12）。集めたくなる見た目にする。
- 行ったお店に、星・ひとこと・写真 1 枚の感想を残せるようにする（SPEC S12〜S14。今まで「準備中」の枠だった）。
- ほかの人の感想を見られるようにし、不適切なものは通報できるようにする。

## オーナーの決定
- 見た目は **案B コレクションカード**（見本 `.superpowers/preview/zukan2/`、`?d=B&s=list|detail`）。案A・C・D（ドロップシール）は採らない。
- **感想は 1 件ごとに公開・非公開を選べる**（2026-11-12 追加）。既定は公開（S12「みんなが見れる」に合わせたリーダーの判断）。非公開の感想と写真は本人だけが見られ、みんなの感想の件数・平均にも入らず、通報もできない。
- 感想を書ける所は **案1**：チェックインの直後と、図鑑の詳細の「書く・直す」。
- 前からの決定:
  - 感想は 1 回のチェックインに 1 件（D-03）。
  - 星は 1〜5、ひとことは 1〜500 文字で任意、写真は 1 枚までで任意。
  - 公開はログインした人全員。名前はニックネームで出す。
  - 自分の感想は編集・削除ができる。
  - 通報を付け、管理者が Supabase の画面で非表示（`hidden`）にする。
  - 写真は非公開のバケット `review-photos` に置き、期限付き URL で見せる。端末で 150〜250KB に縮める。撮った場所などの情報は残さない。

## 非目標
- 共有の画像（S14 の記念画像）。共有のボタンは今回は出さない。
- 図鑑の並べ替え・検索。
- 住所・営業時間（`shops` に列が無い）。見本の「お店の情報」の枠は出さない。
- 通報の理由の選択（表に列が無い。通報は 1 タップ＋確認だけ）。
- 丸い字体をアプリ全体に広げること（今回は図鑑・感想の画面だけ。iPhone で見てから決める）。
- 霧の中のお店の感想を見せること（S1）。

## 画面
### 1. 図鑑の一覧（案B）
- 台紙はクリーム色に斜めの縞。タイトルは橙のリボン。
- 進み具合は白い箱に入れる：
  - 左にコレクション率の円グラフ（%）。
  - 右に「Lv n・コレクション 埋めた数 / 全部」、EXP のバー、「次の Lv まであと n EXP」。
- ジャンルのタブ：ピンの絵＋名前の丸いボタン。選ばれたタブは茶色。横にスクロールする。
- 「ラーメン 5 / 9」の行。並べ替えは出さない。
- カードは 3 列で、今と同じくページで送る（`PAGE_SIZE`）。
- 行ったお店のカード：
  - 枠は濃い茶色の線＋平らな色。段は 銅（1〜2 回）・銀（3〜9 回）・金（10 回〜）で、光の帯と右下の濃い縁で金属に見せる（`frameTier`。2026-11-12 オーナー「AI っぽい」→ 案1 改、右上の印は無し）。
  - 左上に `No.001`（ジャンルの中の並び順＋1、3 桁）。
  - 絵の窓には、ホットペッパーの写真か、無ければ種類の絵。
  - 茶色の名前の札。
  - 下の段に、お店の特徴（ホットペッパーのひと言、無ければ「はじめて 11.07」＝カードを手に入れた日。ジャンルは出さない）と「n回」。~~自分の感想の星~~（2026-11-12 オーナー「感想じゃなくてお店の特徴」で変更）。
- まだ行っていないお店のカード：むらさきの「カードの裏」に、シルエットと「？」、「？？？」、キャッチを出す。押せない（今と同じ）。

### 2. 図鑑の詳細（案B）
- 上の段：「‹」（戻る）と `No.001`。
- 大きなカード：
  - 枠の色はそのお店の段（ふつう・銀・金）。
  - 中に写真（「公式の写真」の札）、茶色の店名の札、ジャンル・予算・「金の枠」の丸い札、キャッチ。
  - 右上に赤い「訪問済み 日付」のはんこ。
- 数字の 3 つの箱：行った回数・はじめて・この前。
- **わたしの感想**：
  - いちばん新しい訪問の感想を出す。星、日付、ひとこと、写真（ポラロイド＋テープ）。非公開の感想には「🔒 自分だけ」の札を付ける。
  - 右上に「書く・直す」。
  - 前の訪問の感想があれば「前の感想（n件）」でたたんで下に並べる。
  - 1 件も無ければ「まだ感想がありません」と「感想を書く」。
- **みんなの感想**：
  - 見出しに件数と平均の星。自分の感想は数に入れない。
  - 新しい順に 10 件ずつ、「もっと見る」で次の 10 件。
  - 1 件ごとに、丸い頭文字、ニックネーム、星、ひとこと、写真（小さく。押すと大きく）、「⋯」（通報）。
  - 0 件なら「まだ感想がありません」。
- 下に「地図で見る」（今と同じ）。
- まだ行っていないお店の詳細は今までどおり開かない。

### 3. 感想を書く画面（全画面のシート、案B の茶色の線と橙のボタン）
- 店名と、どの訪問かの日付。
- 星 5 つ。押して選び、必須。
- ひとこと：500 文字まで、残りの文字数を出す。
- 写真：「写真を選ぶ」（iPhone ではカメラかアルバム）。選ぶと見本が出て、「外す」もできる。
- 「みんなに見せる」のスイッチ（既定はオン）。オフにすると「自分だけ」と出る。
- 「保存」。直すときは、ほかに「この感想を消す」（確認あり）。
- 保存中はボタンを止めて「保存しています…」。失敗したら「保存できませんでした。もう一度押してください」。書いたものは消さない。

### 4. チェックインの直後
- 紙ふぶきの演出が終わったら、画面の下に「✎ 感想を書く」の丸いボタンを 10 秒出す。押すと 3. を、そのチェックインで開く。押さなければ消える。
- 書くのはあとから図鑑でもできるので、ここで書かなくても何も失わない。

### 5. 地図のお店のシート
- 行ったお店でも行っていない晴れたお店でも、シートに「みんなの感想 ★4.3（12件）」と、新しい 2 件（名前・星・ひとこと）を出す。写真と通報は図鑑の詳細だけにする。
- 霧の中でシートを出さないお店には出さない（今と同じ）。

## 作り（リーダーの判断）
- **新しいフォルダ `src/reviews/`**
  - `domain/review.ts`：
    - 型 `Review`（id・checkinId・shopId・userId・stars・body・photoPath・createdAt・nickname）。
    - 入力の確かめ `validateDraft`（星 1〜5、ひとことは前後の空白を除いて 0 なら null、500 文字以下、`isPublic` は真偽）。
    - 平均 `summarize(stars[])`（小数 1 桁、0 件は null）。
    - 自分の感想の並べ方 `myReviewsByVisit`（新しい順、いちばん新しい訪問の感想が先頭）。
    - 書く先のチェックインを決める `targetCheckin`（いちばん新しい訪問。感想があれば「直す」）。
  - `infra/reviewsApi.ts`（Supabase）：
    - 店ごとの自分の感想とチェックインを読む。
    - みんなの感想を読む：`hidden = false`、自分を除く、新しい順、10 件ずつ。ニックネームは `public_profiles` を `user_id in (...)` で読んで合わせる。
    - 件数と平均は、その店の `stars` 列だけを読んで端末で計算する（今の数なら軽い。増えたら SQL の関数にする）。
    - 作る・直す・消す。
    - 通報：`review_reports` に `review_id` だけ入れる。一意違反なら「通報済み」として成功扱い。
    - 写真の期限付き URL は `createSignedUrls` で 1 時間、まとめて取る。
  - `infra/photo.ts`：
    - `createImageBitmap(file, { imageOrientation: 'from-image' })` で読み、長い辺を 1080px 以下にして canvas で JPEG に描き直す。描き直すので位置などの情報は消える。
    - 品質を 0.82 から 0.06 ずつ下げて 250KB 以下にする。0.5 でも超えるときは辺を 0.85 倍にしてやり直す。
    - 置き場所は `{uid}/{uuid}.jpg`。
    - 写真を替えたときは、感想を直してから古いファイルを消す。感想を消したときも写真を消す。
  - `ui/ReviewEditor.tsx`（3.）、`ui/ReviewList.tsx`（みんなの感想）、`ui/MyReviews.tsx`（わたしの感想）、`ui/reviews.css`。
- **図鑑**：
  - `Zukan.tsx`・`ZukanDetail.tsx`・`zukan.css` を案B に作り直す。見本の `z.css` の `.dB` を元にする。
  - データは今の `loadZukan` に、自分の感想の星（店ごとのいちばん新しい 1 件）を足す。
- **チェックインの後**：`MapPage` がチェックインの成功で `checkinId` を持ち、演出が終わったら丸ボタンを出す。押したら `ReviewEditor` を開く。
- **お店のシート**：`ShopSheet` に任意の `reviews?: { avg; count; latest[] }` を足す。読むのは `MapPage` で、シートを開いたときだけ。
- **字体**：M PLUS Rounded 1c（SIL OFL、無料）を `@fontsource/m-plus-rounded-1c` で入れる。npm の依存を 1 つ足すだけで、パソコンに入れる物は無い。文字の範囲ごとに分かれていて、使う字だけ読む。使うのは `.zukan`・`.zd`・感想の画面だけ。設定の出典にフォントの名前とライセンスを足す。
- **SQL**：表・RLS・バケットは `0001_init.sql` にある。公開・非公開のために `supabase/migrations/0007_review_visibility.sql` を足す。
  - `reviews.is_public`（既定 true）を足す。
  - 他人が読める感想・写真、通報できる感想を「hidden でない かつ 公開」にする。
  - 本人が `is_public` を書けるように列の GRANT を足す。
  - 他人に見せない決まりは RLS で守る（アプリの絞り込みに頼らない）。オーナーに SQL Editor で流してもらう。

## 守ること
- 依存の向きは ui → infra → domain。domain は何も import しない。
- 写真は描き直してから送る（元のファイルは送らない）。250KB を超えたら送らない（バケットの上限は 300KB）。
- 他人の名前は `public_profiles` のニックネームだけ。
- 霧の中のお店の感想は出さない（S1）。
- テストで確かめること：
  - `validateDraft`、`summarize`、`targetCheckin`、`myReviewsByVisit`。
  - API の読み取り（壊れた返事・0 件・通報の重複）。
  - 図鑑のカードの段・No.・星・「感想まだ」。
  - 感想の画面（星が無いと保存できない、500 文字の上限、保存の失敗で文が残る）。
  - チェックインの後の丸ボタン（10 秒で消える・押すと開く）。
  - お店のシートの感想の行。

## 残り・リスク
- iPhone の HEIC の写真：Safari の `createImageBitmap` で読める（iOS 17 以降）。読めなかったら「この写真は使えませんでした」と出す。
- 感想が増えると、平均の計算で `stars` を全部読むのが重くなる。そのときは SQL の関数にする（今は不要）。
- 期限付き URL は 1 時間で切れる。開き直せば取り直す。
