# ガチャ（A15）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** コインでキャラを引き（単発・10 連）、持っているキャラを一覧で見て、使うキャラ（左上の絵・地図の上のアバター）を変えられるようにする。

**Architecture:** 抽選・引き落とし・持ち物・なかよし度はサーバーの SQL 関数 1 つ（`draw_gacha`）が 1 トランザクションで決める。アプリは `src/gacha/`（domain: キャラの一覧・返事の読み取り・なかよし度と天井の計算／infra: SQL 関数を呼ぶ／ui: ガチャ画面・引く画面・キャラ一覧）。使っているキャラは `profiles.current_character_id`（空なら最初のキャラ）。地図のアバターは、そのキャラの 3D（`src/assets/characters/<id>/avatar.glb`）が無ければ原画を 2D で出す。

**Tech Stack:** React 19 / TypeScript / Vite / Supabase（Postgres の SQL 関数）/ Vitest＋Testing Library / MapLibre＋three.js（アバター）

**Spec:** `docs/superpowers/specs/2026-11-17-gacha-design.md`（決まりの元は `docs/SPEC.md` A15）

## Global Constraints
- 1 回 100 コイン、10 連 1000 コイン（0001 の `gacha_sessions` の CHECK と同じ）。課金なし・出るのはキャラだけ。
- 排出率 ★3 70%／★4 25%／★5 5%。★を決めてから、その★の「入っている」キャラから等しく選ぶ。
- 10 連は ★4 以上が 1 体確定（1〜9 体目に無ければ 10 体目を ★4 以上に。そのときの ★5 は 5÷30）。
- 天井: 前の ★5（無ければ最初）から数えて 30 回目は ★5。`guarantee` の印は ceiling ＞ ten_floor ＞ none。
- 最初に入っているのは 01・05・06・14・26 の 5 体だけ（`characters.in_pool`）。
- なかよし度 = `user_characters.duplicate_count` を 5 で止めて見せる。数は数え続ける。見た目だけ。
- ゲストも引ける。
- サーバーで決める。端末で抽選しない。キーをソースに書かない。
- 画像（ミシェーラに依頼中 `handoff/to-shiro/2026-11-17-gacha-screens-art.md`）が無い間は CSS の色と形で仮に作り、`src/assets/gacha/ui/` に置かれたら差し替える。
- 新しい道具は入れない（画像の縮小は Blender の台本で）。
- 演出は押せば飛ばせる。`prefers-reduced-motion` なら光だけ。

## Review Focus
1. 同時に 2 回押す／通信が遅く 2 回送られる → コインが 2 重に引かれたり、天井が 2 重に数えられたりしない（`gacha_draws` の `unique (user_id, user_pull_no)` と行の固め）。
2. 残高が足りない → 何も書かずに `insufficient` を返し、画面は「コインが足りません」。ボタンは残高で先に押せなくする。
3. 通信が切れて返事が来ない → 画面は「もう一度」を出し、コインの数字は読み直す（引けていたかもしれないので、持ち物も読み直す）。
4. 持っていないキャラを `set_character` で指定 → サーバーが断る。
5. 3D の無いキャラを使う → 地図のアバターが消えず、原画の 2D が出る。3D のあるキャラへ戻すと 3D に戻る。

### Task 1: SQL 0014（入っているキャラ・使っているキャラ・引く・変える・状態）

**Files:**
- Create: `supabase/migrations/0014_gacha.sql`

**Interfaces:**
- Produces（SQL 関数。どれも `security definer`・`search_path = ''`・`auth.uid()` が無ければ `28000`、`authenticated` に execute）:
  - `draw_gacha(p_type text)` → `table (pos smallint, character_id smallint, rarity smallint, guarantee text, is_new boolean, friendship integer, status text)`。`p_type` は `'single'`／`'ten'`。足りないときは 1 行 `status = 'insufficient'`（他は null）。成功は 1 行または 10 行、`status = 'ok'`。
  - `set_character(p_character_id smallint)` → `text`（`'ok'`／`'not_owned'`）。101・102 はいつでも ok。
  - `my_gacha_state()` → `table (pulls_since_five integer, current_character_id smallint)`。
  - `my_characters()` → `table (character_id smallint, duplicate_count integer, obtained_at timestamptz)`（`user_characters` の自分の行。RLS で select できるが関数でそろえる）。

- [ ] **Step 1: 0014 を書く**
  - `alter table characters add column in_pool boolean not null default false`、01・05・06・14・26 を true。`name` に 30 体の名前（`art/gacha/chars/char-roster.md`）を入れる。
  - `alter table profiles add column current_character_id smallint null references characters(character_id)`。書き込みは `set_character` だけ（列の grant はしない）。
  - `draw_gacha`: `pg_advisory_xact_lock(hashtextextended('gacha:'||uid,0))` → `coin_balances` で残高を確かめる → `gacha_sessions` に 1 行 → 1 体ずつ: 通し番号 `user_pull_no` = これまでの最大＋1、天井の判定（前の ★5 の番号からの差が 30 以上なら ★5）、10 連の 10 体目の確定、`random()` で★、その★の `in_pool` から `order by random() limit 1` → `gacha_draws` に入れる → `user_characters` に upsert（あれば `duplicate_count + 1`、`is_new` は前に無かったか）→ `coin_ledger` に `('gacha', -cost)`。`gacha_draws` に session との紐付けがあるので `coin_ledger` 側の列は 0001 の定義に合わせる（無ければ reason と amount だけ）。
  - 0001 で `gacha_*`・`user_characters` は「書き込みは Edge Functions のみ」（service_role）だが、この関数は `security definer` なので書ける。コメントで「0014 から SQL 関数で書く」と残す。
- [ ] **Step 2: 自分で読み直す**（0011 の `claim_present` と同じ形か、grant、ten の確定が 10 体目だけか、天井が「30 回目」で 29 でも 31 でもないか）。
  Expected: 書き方の点検だけ（このリポジトリに SQL のテストは無い。動作はオーナーが dev の Supabase に流して、アプリで確かめる）。
- [ ] **Step 3: Commit** `git add supabase/migrations/0014_gacha.sql && git commit -m "gacha SQL 0014: ..."`

- [ ] **Step 1: 失敗するテストを書く**

  - `parseDrawResult([{status:'insufficient', pos:null,...}])` → insufficient
  - `parseDrawResult('x')`・`[]` → null

  - `CHARACTERS` は 32 件、`inPool` は 5 件（01・05・06・14・26）、★5 4・★4 8・★3 18
