# 3D を作るときのトークンを減らす — 調べたことと設計（キャラ・お店）

- 日付: 2026-11-26（オーナー「毎回 Blender に作らせたときにトークンがかかりすぎ。MCP で減らせないかなど正しいやり方を再調査・設計して。お店とキャラは別で。お店は右の絵（温かい光・柵・街灯の、立体的なジオラマ）のような感じ」）
- 決めたこと（同日）: **図鑑のお店の絵はジャンルごとに 1 種類、看板に店名は入れない**（看板に名前は不自然になるため）。お店の見た目の見本: `art/reference/zukan-v3/shop-ramen-ref.png`（右の絵）。
- 関係: キャラの手順の正本 `avatar-character-pipeline.md`、ガチャ 5 体 `2026-11-25-gacha-3d-five.md`、図鑑 v3 `2026-11-25-zukan-v3-design.md`。

## 1. これまでトークンがどこで使われたか（男の子・女の子・キリン）
| 使い道 | 中身 | 割合の見込み |
|---|---|---|
| Blender の台本を毎回書く・直す | サブが形・重み・動き・撮影の長い Python をその場で書き、失敗して書き直す | いちばん大きい |
| 画像を見る | 1 枚 約 1,600 トークン（1280×720）。6 方向×8 コマ×4 動きの並べ画像・拡大 10〜14 枚を、サブとリーダーの両方が見る。見た画像は会話に残り続け、その後の 1 回ごとに読み直しになる | 大きい |
| 文脈を集め直す | まっさらのサブが方針書・設計書・前の台本を毎回読む | 中 |
| 試行錯誤 | 同じ所を数回直す | 中 |
（男の子は Opus で約 100 万、キリン・女の子は 30〜40 万）

## 2. 調べたこと（2026-11-26）
- **Blender の MCP**: よく使われているのは個人の [blender-mcp](https://github.com/ahujasid/blender-mcp)（PyPI は mcp-for-blender）。開いている Blender を会話から 1 手ずつ動かし、画面の写真を返す作り。Blender 公式の MCP（Blender Lab、5.1 以上）があるという記事は 1 件だけで、公式の頁では確かめられなかった。
- **MCP はトークンを減らさない**: 画面の写真がいちばん高く、写真は会話に残って毎回読み直される（[画面の写真の費用](https://dev.to/uwe_c_39d9ab7d16ff8dfe67e/screenshots-cost-25000-tokens-i-got-it-down-to-750-3p8d)）。Blender の MCP でドーナツ 1 つを作った試しで、月額の上位プランの 1 回分の 60% を使ったという報告がある（[MindStudio](https://www.mindstudio.ai/blog/claude-blender-mcp-60-percent-tokens-donut-test-results)）。道具の説明も毎回読み込まれる。さらに blender-mcp は、画面の写真を含むデータを集めて学習に使うことがあると書いてある（設定で切れる）。
- **減らせるのは**: 決まった台本を数字だけ替えて流す・合否はまず文字（数字）で返す・画像は区切りだけで小さく、のやり方（同じ記事の一般的な助言）。
- **形を作る AI**: [Hunyuan3D 2.1](https://huggingface.co/tencent/Hunyuan3D-2.1) は質感（PBR）まで作れるが、色を塗る工程に VRAM 21GB が要る。今の機械（形の工程で 4.4GB を使用）には重いので、**今の Hunyuan3D-2mv（3 方向入力）を使い続ける**。形と色は別の工程なので、形だけ先に確かめられる。

## 3. 方針（キャラ・お店に共通）
1. **MCP は入れない。** 作業は「決まった台本に数字を渡して流す」形で、会話から 1 手ずつ動かす必要がない。画面の写真を返す作りは、いちばん高い使い道を増やす。
2. **台本を 1 回だけ作り込み、以後は設定ファイル（`config.json`）を替えるだけにする。** 段ごとに 1 つのコマンド（`blender -b -P <段>.py -- config.json`）。サブは台本を書かず、設定を替えて流し、結果の数字を読む。台本の直しが要るときだけリーダーが直す（直した台本は全キャラで使い回す）。
3. **合否はまず数字（文字）で。** 各段の台本が、関門の項目を JSON で出す（島の数・重みの 100% の例外の数・はみ出し・三角形・容量・足の裏の高さ など）。数字が通ったときだけ画像を撮る。
4. **画像は区切りだけ、1 枚にまとめて小さく。** 関門ごとに並べ画像 1 枚（長い辺 1200px）＋拡大は 1 枚にまとめて 1 枚。見るのは**リーダーだけ**（サブは画像を見ずに数字で止まる）。オーナーに送る動画・画像は今までどおり。
5. **ComfyUI はアプリ側（WSL）から HTTP で動かす。** 絵の送り込み（`/upload/image`）・実行（`/prompt`）・できた物の取り出し（`/view`）を台本で。オーナーは ComfyUI を起動するだけ（今の「ファイルを写す・別の窓で実行」が要らなくなる）。comfy-mcp は使わない（同じことを MCP でやると説明が毎回載る）。**確かめた（2026-11-26）**: WSL から 127.0.0.1:8188 には直接届かない（ComfyUI は Windows の中だけで受ける）。**Windows 側のコマンドを WSL から呼ぶ**と届く: `powershell.exe -NoProfile -Command "cd D:\mogumo-3d; venv\Scripts\python.exe tools\run_char_mv.py <名前> <種> <ラベル>"`。入力の絵と台本の写し（`/mnt/d/mogumo-3d/...`）も、サンドボックスの外で Claude が写せる。オーナーは ComfyUI を起動するだけ。
6. **サブは Sonnet で流す。** 台本が決まっている作業なので。Opus は、新しい体型の最初の 1 体と、原因の分からない崩れのときだけ（CLAUDE.md の決まり）。
7. **使う量の上限を段ごとに決め、超えたら止めて報告。**

## 4. キャラ（ガチャ 5 体）
- 台本の元: `art/characters/boy/scripts/`・`art/characters/01-hoshifuru-kirin/scripts/`（`build.py`・`repaint.py`・`stance.py`・`gate1-probe.py` など）。これを **「動物の二本足」型の台本**にまとめる（骨 14＋しっぽ 0〜2＋耳 2、手首・ミトン 4）。キャラごとの違いは設定に書く:
  - 区分けの色（毛・おなか・肉球・リュック…）と、塗り直しの色（元の絵から測る）
  - しっぽの骨の数（ねこ 2・ほかは 0＝腰に 100%）、耳の骨の有無
  - 持ち物（クッキー・串）を付ける骨
  - 立ち姿・歩き・走りの数（足の長さ・歩幅・腕の開きは、**台本が形から測って**最初の値を決める。原則 5「動きはキャラごと」）
- 段と流し方（1 体）:
  | 段 | すること | 誰が | 目安 |
  |---|---|---|---|
  | 1 | ComfyUI で形と色（種 3 つ）→ 関門 1 の数字（島・しっぽ・リュック）→ 並べ 1 枚 | 台本＋リーダーが見る | 2 万 |
  | 2〜3 | 塗り直し・骨・重み（設定だけ替えて流す）→ 数字 → 試しの姿勢 1 枚 | サブ（Sonnet） | 4〜6 万 |
  | 4〜6 | 顔・動き・撮影 → 数字 → 並べ 1 枚＋拡大 1 枚 → 動画 | サブ（Sonnet）＋リーダーが見る | 4〜6 万 |
  | 7 | アプリに置く・圧縮 | リーダー | 1 万 |
  合計 **1 体 10〜15 万**（今の 30〜40 万から）。ただし、**最初のねこは台本を作り込む分で 30〜40 万**（新しい型の最初の 1 体）。
- 今までの失敗の決まりはそのまま（手のひらは内側・指なし・しっぽを離す・色は塗り直し・立ち姿は元の絵に・拡大で見る）。

## 5. お店（図鑑のジオラマ）
- 見た目の見本: 右の絵（屋根の瓦・柵・植木鉢・街灯・のぼり・立て看板・暖かい窓の光、四角い石の台座）。地図の今の模型より細かい。
- 作り方: ギルベルトの 3 方向の絵 → ComfyUI（形と色）→ **Blender の決まった台本 1 本**（向き・台座を水平に・大きさ・原点・窓とちょうちんを光る材質に・meshopt で圧縮）。骨・動き・顔が無いので、キャラより段がずっと少ない。煙・きらきらは画面の CSS で動かす（3D に入れない）。
- 1 種類の流れ: 生成（種 2〜3）→ 数字（三角形・容量・台座の傾き・穴）→ 並べ 1 枚（4 方向）をリーダーが見る → 置く。目安 **1 種類 2〜4 万**（最初のラーメンは台本を作る分で 8〜10 万）。18 種類で 40〜80 万。
- 大きさ: 1 つ 5〜8 万三角形・2〜3MB 以内。図鑑の詳細を開いたときだけ読む。
- 地図の模型をこのジオラマに替えるかは、別に決める（地図は何百軒も出るので、そのままでは重い。軽くした版を作るかは、ラーメンのあとで相談）。

## 6. 順番
1. ねこ（ガチャ）で「動物の二本足」型の台本を作り込む（ComfyUI を HTTP で動かす台本も、ここで作る）。
2. しば → くま → うさぎ → キリンは設定だけ替えて流す。
3. お店はラーメンの絵が届いたら、ジオラマの台本を作り、図鑑 v3 の画面と一緒にオーナーに見せる。ComfyUI はガチャのあと（同じ機械を順番に使う）。
