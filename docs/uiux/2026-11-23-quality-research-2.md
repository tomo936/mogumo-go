# UI の質を上げる方法の再調査（2026-11-23。サブエージェントが web で調べたもの）

## いちばん大事な発見
**ログインボーナスが良く見えるのは、枠・リボン・皿が「描いた絵」だから。** 他の画面は CSS の箱（角丸・影・線）で作っていて、それが AI っぽさ・安っぽさの元。
プロも個人＋AI の実例も、「先に画面の絵（コンセプト）を作る → 同じ参照から部品の絵を透明背景で作る → 伸びる枠は 9-slice（CSS の border-image）で使う → コードで組む」の順（SpriteCook https://www.spritecook.ai/blog/generate-game-ui-with-ai 、border-image の作り方 https://guide.coherent-labs.com/layout-assets-and-styling/graphics--shapes/advanced-ui-shapes/ ）。
失敗の理由は、部品ごとに別の依頼で作って光・色・枠の太さがずれること、9-slice 無しで拡大して角が歪むこと。

## A. プロのゲーム UI
- 色は少数のパレットを番号で参照、形の決まりを全画面に同じように使い、例外を作らない（Beastieball https://www.gamedeveloper.com/art/deep-dive-developing-a-clear-and-consistent-visual-language-in-the-ui-of-beastieball ）
- 絵の「形の言語」を先に決め、UI をそれに合わせて作る（Duolingo https://blog.duolingo.com/shape-language-duolingos-art-style/ ）。主要ボタンは下に濃い縁、押すと沈む
- ボタンは 通常・押下・無効 の状態を用意。無効は見ただけで分かるように
- 有名ゲームの UI の中身（スタイルガイド等）の一次資料は見つからなかった

## B. AI っぽさ
- 原因は学習データの平均への収束（Anthropic https://claude.com/blog/improving-frontend-design-through-skills ）。禁止リストより具体的な見本を渡すほうが効く
- 作り手の判断を見せる: 色を機能に結ぶ／役割ごとに角丸・余白・大きさを変えて主役を大きく／分離は影・枠・色の 1 つだけ／空・読み込み・エラーの状態を作る／サイズと太さの差を大きく

## C. コレクション画面の使いやすさ（根拠は弱い）
- 上に「集めた数 / 全体」と進み具合、「まだ」だけ見る絞り込み、並べ替え。未発見は名前を隠しすぎず手がかりを残す（今の仕様どおり）。一覧から詳細まで 1〜2 回
- 悪い例: ポケモン GO の 2025 年の図鑑（足りない物が見えない・数が不正確）

## E. もぐもGO の手順（世界観は変えない）
1. ログインボーナスを基準画面にして、色・輪郭線・影・角丸・余白を数値で抜き出す
2. 部品の最小セット（ボタン 4 状態・紙の枠・札・リボン・タブ・数の札・閉じる）を 1 枚のスタイル見本で作って見る
3. 枠・リボン・札は ChatGPT で「ログインボーナスの絵に合わせて」1 回でまとめて作り、9-slice で使う
4. Web 部品のままの画面を部品に置き換える
5. 決まりに無い飾り（グラデーション・ホロ・傾き・きらめき）は使わない
6. 画面ごとに主役を 1 つ
7. 図鑑は今の作りのまま、「まだ」の絞り込みと並べ替えを足す候補
8. 空・読み込み・エラーの状態を作る
9. 押した感触を統一
10. 1 画面ずつ: 見本の絵 → HTML/CSS → 撮影 → 見本と並べて直す
11. 使いやすさは前後で数える（押す所の大きさ・押す回数・文字）
12. 「新しい飾りはログインボーナスの決まりにあるものだけ」を決まりにする
