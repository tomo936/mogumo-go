# 実装ステップ3a「地図表示・傾け・現在地追従」設計

日付: 2026-11-05 ／ 承認: 本人（方式 A）／ 対応: PLAN-cycle1「積む順番」3 の前半、基本設計 5.1・5.2、N-17（検知サークル）
後半の 3b（アバターの歩行）はシロのスプライトが届いてから別の設計メモで扱う。

## 目的と理由
アプリを開くと、自分のいる場所のまわりの地図が斜め見下ろしで出て、歩くと地図がなめらかについてくる。イメージはポケモンGO（本人）。PLAN の受け入れ条件「iPhone 16 で地図がヌルヌル動く」「歩いてもブレずについてくる」の土台で、3b のアバター・4 のお店ピンと霧はこの地図の上に載る。

## ゴール
- ログイン後の `/`（今の仮の地図画面）を本物の地図に置き換える
- 地図は MapLibre GL JS＋OpenFreeMap。pitch 55°の斜め見下ろし
- **自分は常に画面の中心に固定**（本人決定）。指でずらして別の場所を見ることはできない
- 1本指の横なぞりで、自分を中心に地図が回る（ポケモンGO 方式）。ピンチで少しだけズーム（町並みが見える範囲に限定）
- 方位磁石による自動回転はしない
- 自分の位置は、足元の影と**半径 50m の検知サークル**で表す（N-17 の決定：チェックイン距離に合わせる）。人の絵は 3b で載せる
- GPS（`watchPosition`）の位置を目標にして、毎コマ（requestAnimationFrame）カメラを少しずつ寄せる。GPS の飛び（精度の悪い測位）はならす／捨てる
- 位置情報が使えない・断られたとき: 地図の代わりに「位置情報をオンにしてください」と「もう一度試す」ボタン
- 出典表示（OpenFreeMap／OpenMapTiles／OpenStreetMap）を常に表示
- タイル（スタイル URL）の出どころは設定1か所で差し替え可能
- 開発中だけ「歩いたふり」ができる仕組み（PC で動きを確認するため）。本番ビルドでは無効
- ログアウトボタンは残す（マイページができるまでの仮置き）

## やらないこと（非ゴール）
- アバターの絵と歩行アニメ（3b）
- 気配タップでカメラが一時的に寄る動き（気配機能＝PLAN 5 で作る）。ただしカメラの持ち方は、後で「一時的に別の場所を見て戻る」を足せる形にしておく
- 記録（開拓記）画面の自由に動かせる地図（PLAN 5。本人要望：記録からは地図を自由に見たい）
- お店ピン・霧・自宅設定
- 地図スタイルの作り込み（明るい既成スタイルを土台に色を寄せる程度。細かい見た目は実物を見ながら別途調整）

## 失敗とみなすこと（アンチゴール）
- 地図の移動・GPS 更新・毎コマの描画で React が再描画される（PLAN 技術リスク）
- 位置がカクカク、またはブレて震える
- 位置情報を断ると真っ白・固まる
- 現在地や移動履歴をサーバーや外部に送る（タイル取得以外の通信を増やさない。自宅座標の原則と同じ考え方）

## 制約
- CLAUDE.md のツールチェーン（import type、拡張子付き import、enum 不可、noUnused*、Oxlint）
- 完全無料：OpenFreeMap（キー不要）。アクセスの節度を守る
- 地図・カメラ・GPS・補間後の位置は MapLibre インスタンスと ref／React 外のモジュールで持つ（基本設計 2.3）
- iPhone の Safari 優先。位置情報は HTTPS でのみ取れる（Vercel の本番 URL で確認）
- 画像素材は使わない（影とサークルは図形で描く）

## 方式の比較（追従のなめらかさ）
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）自前の描画ループ** | 毎コマ、最新の GPS 位置へカメラを少しずつ寄せる | 更新間隔がばらついてもなめらか。飛びをならせる。3b の歩行コマと同じループで同期できる | コード量が増える。iPhone での確認が必須 |
| B GPS 更新ごとに1秒で移動 | 更新のたびに easeTo | 簡単 | 間隔がずれるとカクつく。歩行と合わせにくい |
| C MapLibre 組み込みの追従 | GeolocateControl | 最も楽 | 決まった青い点、ならし方を調整できない、触ると追従が外れる（中心固定にできない） |

本人が A を選択（2026-11-05。「ポケモンGO もそうだよね」）。

## 決まっていること
- pitch 55°、中心固定、1本指の横なぞりで回転、ピンチで限定ズーム、自動回転なし
- 検知サークル 50m（地図の傾きに合わせて楕円に見えること）
- 位置情報エラー時は案内＋再試行ボタン
- 開発用の「歩いたふり」は本番で無効

## 位置情報のエラーの扱い（チェック役の質問を受けてリーダーが提案、本人承認 2026-11-05）
- **歩いている途中で GPS が途切れたとき**（電波が弱い・屋内・一時的なタイムアウト）: 地図は消さず、最後の位置のまま止めて、画面上部に小さく「位置情報を待っています…」と出す。取れたら自動で消える。
- **全画面の案内にするのは次の2つだけ**:
  1. **位置情報を断られた**とき: 「位置情報がオフになっています」＋「iPhone の『設定』→『プライバシーとセキュリティ』→『位置情報サービス』→『Safari の Web サイト』で『使用中のみ』にしてから、このページを再読み込みしてください」＋「再読み込み」ボタン。iOS は一度断ると再び許可を聞かないため、「もう一度試す」ではなく再読み込みにする。
  2. **最初の位置がいつまでも取れない**とき（断られてはいない）: 「現在地が見つかりません」＋「もう一度試す」ボタン。
- **しばらく途切れたあと、大きく離れた場所で位置が戻ったとき**（バックグラウンドから復帰など）: 一定時間以上途切れていたら、ならさずに新しい場所へ一気に移す（ならし続けて本物の位置を捨て続けないため）。短い間隔で飛んだ位置だけを「飛び」として捨てる。しきい値は作る人に任せる。

## 作る人に任せること（リーダーの判断として記録）
- ズームの範囲（目安 16〜18）、初期ズーム、回転の感度
- ならし方（例: 精度が一定以上悪い測位を捨てる、寄せる速さ）。値は実機で調整できるよう1か所にまとめる
- 影とサークルの描き方（地図レイヤーか、画面中央の重ね表示か）。傾きで楕円に見えることが条件
- 「歩いたふり」の起動方法（URL のパラメータ等）と動き方（決まった道を歩く等）
- 最初の位置が取れるまでの表示（「現在地を探しています…」等）
- テストの範囲: 位置のならし・回転の計算・エラー表示など、地図を描かずに確かめられる部分は単体テスト。地図の見た目となめらかさは本人の実機確認
