# 大型施設（実際の形の立体）と駅の設計

2026-11-07。前の段: `2026-11-07-multi-shop-building-design.md`（ビル。§8 で大型の決め方を広さに変えた）。

## 1. ねらい
- デパート・駅ビル・ショッピングモールのような大きい建物は、ビルの模型ではなく **地図の実際の形をかわいく立体にして** 出す（本人決定 2026-11-07）。「まるでそこにあるように」。
- 駅は駅だと分かるようにする（本人 2026-11-07「駅なら駅の見た目の方がいい」）。

## 2. 決まったこと（本人）
- 大型 = **輪郭の広さ 2,500m² 以上で、お店が2軒以上**（前の段 §8）。
- 見た目: 実際の輪郭を立ち上げる。色・飾りはシロの見本 `art/reference/shops/facility-large.png`（壁クリーム #f6ead7、階ごとの窓の帯 #91cfe7、屋根のふちと窓枠は木色 #8e5c42〜#b7a08a、入口に赤白しまのひさし #e4745f、屋根に植木と室外機）。
- ピン: 遠くでは施設の上にピン1つ＋「済み/全部」（施設ピンの絵 `art/pins/facility.png`）。拡大すると、ピンが屋根の上の各お店の実際の位置に散らばる。重なる所は少しずらし、多ければ「+N」。施設の中でばらけない店（同じ点に集まる店）は一覧だけ。
- **駅は「大型施設に付ける飾り」**（本人 2026-11-07 OK）: 大型の輪郭の中に鉄道の駅の点（地下鉄ではない）があれば、その点に小さなかわいい駅舎の飾り（三角屋根・時計・改札の入口）を添える。2,500m² 未満の建物に駅の点があり、お店が2軒以上なら、ビルの代わりに駅舎の模型を置く。駅舎の見本はシロに頼む。
- **チェックインは今のまま、お店の点から 50m**（本人決定 2026-11-07、案 A）。輪郭から測る案は、縦に長い建物で上の階の店に下からできてしまうので採らない。サーバーは変えない。

## 3. 実データで分かったこと（2026-11-07）
- 地図タイル（z14）の区切りで建物が切られ、かけらになる（経堂コルティ: 5,546m² と 1,858m² のかけら）。点を含む輪郭のうち一番大きいものを使う直しは前の段で入れた。立体にするときは、かけら同士の重なり（区切りの両側に少しはみ出して入っている）で屋根がちらつかないようにする。
- 同じ場所に高さ違いの輪郭が何枚も重なる建物がある（伊勢丹: 6枚、高さ 5〜30m）。
- 駅と施設が1つの輪郭のことがある（東京駅: 15,284m² の中に「東京駅一番街」と飲食 28軒）。駅の点が百貨店の輪郭の中のこともある（新宿: 京王百貨店）。
- 地図タイルの poi 層: 駅は `class=railway`（`subclass=station`、地下鉄は `subway`）。施設名の点は `subclass=mall` / `department_store`。

## 4. 作り方の候補
- **A. three.js で輪郭を立ち上げる（採用）**: お店の層（`shopLayer` と同じ three のカスタムレイヤー）に、施設の輪郭を `ExtrudeGeometry` で立ち上げた形を足す。壁・窓の帯・屋根のふちを見本の色で付ける。かわいさの作り込みができる。
- B. MapLibre の fill-extrusion で該当の輪郭だけ色を変える: 手軽だが、のっぺりした箱になり、ふち・窓の帯が付けられない。見本に寄せられない。
- C. 大きさの違うビルの模型を何種類か用意する: 形が実物と合わない。本人決定（実際の形）に反する。

## 5. 仕組み
### domain
- `src/shops/domain/facility.ts`（新規）: 施設の形の材料を決める純粋な計算。
  - どの輪郭を立体にするか: 施設の店が入っている輪郭（一番大きいもの）と、同じズームでそれに重なる輪郭（タイルのかけら・高さ違いの部分）。
  - 高さ: タイルの `render_height` をかわいく縮める（例: 高さ × 0.5、最低 6m・最高 30m。`config.ts`）。重なる輪郭は高さが同じなら1枚にまとめる（屋根のちらつき対策）。
  - 階の数（窓の帯の数）: 縮めた高さ ÷ 1階の高さ。
- `src/shops/domain/pins.ts` に、散らばるピンの並べ方を足す: 各店の位置（屋根の上）、近すぎる店どうしを少しずらす、同じ点に集まる店（目安 3m 以内に4軒以上）は「+N」の1つにまとめる。

### infra
- `src/shops/infra/mapFeatures.ts`: 輪郭と一緒に `render_height` と、駅の点（poi 層の railway/station）を取り出す。
- `src/shops/infra/facilityLayer.ts`（新規）か `shopLayer` の拡張: 施設の立体を描く。三角形の数は施設1つで数千まで（輪郭の点の数に比例）。
- `buildingPins.ts`: 施設は、拡大（`FACILITY_SCATTER_ZOOM`、例 17.5）でピンを散らばらせる。縮小では今の「1つ＋済み/全部」。ピンの絵はまず仮の丸で、施設ピンは `art/pins/facility.png` を使う。
- 駅舎の飾りと小さい駅の駅舎の模型: `src/assets/shops/station.glb`（Blender、シロの見本が来るまで仮）。

### ui
- 施設をタップ → 今の一覧のシート（名前の順、長ければスクロール）。散らばったピンをタップ → そのお店のシート。

## 6. しないこと
- チェックインの測り方の変更（本人決定 A）。サーバーは変えない。
- 一覧のジャンルでの絞り込み（長くなったら考える）。
- 施設名の表示（看板・文字は入れない決まり）。

## 7. 作る人に任せること
- 高さの縮め方・窓の帯の間隔・散らばりのズームの値は、画面で見て決める（`config.ts`）。
- 屋根の小物の置き方（輪郭の中に収まる所に少しだけ）。

## 8. 変更: 駅の扱い（2026-11-07 本人、実機確認のあと）
- **駅舎の模型はやめる**（新宿のような大きい駅に合わない）。駅も**実際の輪郭どおりに立体にする**。見た目は「どんな形にも付けられる駅らしさ」をシロの見本で決める（`handoff/to-shiro/2026-11-07-station-shape-art.md`）。ホームの屋根の見た目は「ホームは建物じゃないから変」で却下。
- **駅と複合施設は地図の輪郭どおり**（本人 OK、`art/prototypes/station-combine-mock.png`）: 1つの輪郭なら1つ（名前の札は両方、例「新宿駅・京王百貨店」）、別の輪郭なら別々（経堂駅とコルティ、新宿駅とルミネエスト）。駅ナカの店は駅の輪郭の中なので駅のお店。
- **名前の札**: 大型施設と駅の上に名前を出す（本人の希望）。名前は地図タイルの poi の施設名（mall・department_store）と駅名（railway/station）から。日本語名を優先。
- **区切りの線を消す**: 重なった部分の内側の辺にはふちを付けない（外側の辺だけ）。
- 駅は2,500m² 未満でも、お店が2軒以上なら駅として立体にする（ビルの模型にしない）。
